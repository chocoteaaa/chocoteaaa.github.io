回顾.6主机端口原生作用

139、445 是 SMB 协议端口，原生用途：文件共享、打印机共享（Samba 就是 Linux 上实现 SMB 协议的服务，用来和 Windows 互通共享文件夹）

  • 445：SMB over TCP（主流） 现代 SMB，直接基于 TCP，Windows、Samba 都用这个。现在访问共享文件夹优先走 445。
  • 139：NetBIOS Session Service 老版本，基于 NetBIOS，配合局域网主机名解析，早期 Windows 网上邻居依赖 139；现在很多环境 445 为主、139 保留兼容。

简单理解：这两个端口配套，对外提供共享文件夹服务。靶场里的 myshare 共享，就是靠这两个端口提供。

两个端口剖析

这两个端口同样属于重点攻击对象，139/445端口曾出现过许多严重级别的漏洞。下面剖析渗透此类端口的基本思路。

  1. 对于开放139/445端口的主机，一般尝试利用溢出漏洞对远程主机进行溢出攻击，成功后直接获得系统权限。利用msf的ms-017永恒之蓝。
  2. 对于攻击只开放445端口的主机，黑客一般使用工具‘MS06040’或‘MS08067’.可使用专用的445端口扫描器进行扫描。NS08067溢出工具对windows2003系统的溢出十分有效，工具基本使用参数在cmd下会有提示。
  3. 对于开放139/445端口的主机，黑客一般使用IPC$进行渗透。在没有使用特点的账户和密码进行空连接时，权限是最小的。获得系统特定账户和密码成为提升权限的关键了，比如获得administrator账户的口令。
  4. 对于开放139/445端口的主机，可利用共享获取敏感信息，这也是内网渗透中收集信息的基本途径。

和 80 Web 服务对比

  • 80：HTTP，网页服务，浏览器访问，传 HTML/PHP 文件，给人看页面、提交表单（本题文件管理系统）
  • 139/445：SMB，文件共享服务，不是网页！不能用浏览器直接正常浏览。 Windows 上可以直接 \\172.2.117.8\myshare 访问共享目录；Linux 上用 smbclient 挂载访问。

靶场的限制

  • 跳板机在内网：跳板机本身可以同时连通 172.2.117.5:80 和 172.2.117.8:445
  • 内网穿透是跳板机向外开通道：通道是一对一映射
    • 例：外网端口10080 → 172.2.117.5:80，只能访问 Web
    • 想要外网连 SMB，需要另一条：外网端口10445 → 172.2.117.8:445
  • ⚠️ 不建议随便把 445 直接穿透到公网：SMB 是高危端口，公网暴露极易被扫描、爆破、漏洞利用（比如这个 CVE-2017-7494）

隧道转发

那么既然是一个内网的web服务，但是靶机不出网，kali想要访问必须通过跳板机做转发（172.2.117.5 只有攻击机能到）。但不需要 frp/ngrok 那类”内网穿透”，我们手上的 SSH 连接本身就是一条双向隧道，所以可以把172.2.xxx.x:80的流量转发到本地的8085端口。

有两种方法：

方案 A：ssh -L 本地端口转发（推荐，最简单）

原理：在本机 127.0.0.1:8085 监听，连接进来后，通过 SSH 通道让跳板机去连 172.2.117.5:80。

然后本机浏览器直接访问：

http://127.0.0.1:8085/

登录入口、CKFinder 都能正常点：

http://127.0.0.1:8085/api/index.php?a=login http://127.0.0.1:8085/ckfinder/ckfinder.html

参数含义：

参数 作用
-N 不执行远程命令，只做转发
-f 转入后台
-L 本地：目标：端口 本地监听 → 经服务器连目标
-C 压缩（Web 内容可加，非必需）
ExitOnForwardFailure=yes 转发失败立刻退出，避免 “以为建好了其实没通”
-g 允许同网段其他机器连你的转发端口（默认只绑 127.0.0.1）

原理：本机开一个 SOCKS5 代理，所有流量经跳板机转发，可以访问 整个 172.2.117.0/24，不止一个端口。

三种转发方向别搞混：

写法 谁监听 流量方向 典型用途
-L8085:172.2.117.5:80 你本机127.0.0.1:8085 你 → 跳板机 → 内网Web 访问内网 Web（本题）
-D 1080 你本机127.0.0.1:1080 任意目标经跳板机 扫描 / 多目标

本题要的是第一种：你本机在 “外面”，SSH 客户端就是你，所以天然能做 -L。

为什么不用 frp /ngrok

  • frp 需要一个公网可达的服务端：内网主机主动连出去。本题攻击机连不上公网，而且你也不一定有一个公网 VPS。
  • ngrok 同样要求目标机能出网。
  • 公开 WP 里有人搭两层 frp / 公网 VPS，是因为他们想从浏览器直连内网而又没有可用的 SSH 客户端转发；你这里 SSH 直接可用，一条 -L 就够了。

唯一会失败的情况：平台在跳板机上禁用了 AllowTcpForwarding。刚才实测两个方向都成功，说明没禁。

实操建议

  • 看页面 / 登录 / CKFinder → -L，浏览器访问 127.0.0.1:8085。
  • 扫多个主机 / 端口 → -D + 浏览器代理或 proxychains。
  • 转发默认只绑 127.0.0.1，不要随手加 -g 暴露到局域网。
  • 后台跑用 -fN，排查时加 -v 看通道建立过程；连不上先看有没有 ExitOnForwardFailure 报错。

PHAR 反序列化

利用PHP的 phar:// 协议，去读取这个已经上传好的文件，触发里面的反序列化漏洞（是“触发执行”）

PHAR 是什么

PHAR = PHP Archive，即 PHP 归档包，类似 Java Jar 包，phar://是 PHP 内置流协议，可以读取归档内文件。

核心特点：PHAR 识别依靠文件内容，和后缀无关，改成 png/jpg 依然可以被phar://解析。

反序列化与魔术方法

unserialize()把序列化字符串还原为对象，自动触发魔术方法：

魔术方法 触发时机
__construct() 对象实例化时
__sleep() 序列化之前
__call() 调用不存在方法
__get() 读取不存在 / 私有属性
__set() 给不存在 / 私有属性赋值

如果魔术方法内存在写文件、命令执行等危险操作，就构成 POP 链（gadget 链）。

PHAR 反序列化的特殊机制

常规反序列化：必须代码里直接写unserialize()。

PHAR 反序列化：当使用phar://协议传入文件路径给部分文件操作函数时，PHP 会自动解析 PHAR 清单，自动 unserialize 包内 metadata 元数据。

可用触发函数（只要参数可控）： file_exists()、is_file()、is_dir()、file_get_contents()、fopen()、getimagesize()、md5_file()、unlink()、copy()等。

一句话：PHAR 把普通文件调用，变成了可控的反序列化入口。

PHAR 文件结构

  • STUB 可以拼接图片头，做成多态文件（polyglot），骗过上传校验；
  • metadata 存放我们构造的序列化对象，setMetadata()写入；
  • 私有属性序列化格式：\0类名\0属性名，写错会导致 gadget 失效。

解析：

  • 魔术方法： 代码定义了 __wakeup() 方法，该方法会在对象被反序列化时自动触发
  • 触发路径： __wakeup() 调用了 clear()，而 clear() 又调用了 sendResetMail($this->email)
  • 漏洞细节： sendResetMail 函数使用了 file_put_contents，且写入的文件名和内容部分可控
  • 利用方式： 如果攻击者能控制反序列化过程中的 $this->email 属性，就可以利用 PHP 死亡绕过（Death Bypass） 技术。例如，构造 email 为 ?><?php phpinfo();?>，通过闭合前面的 exit() 来实现 RCE（远程代码执行）
  • 代码末尾虽然没有显式的unserialize()，但在CTF中，通常结合session反序列化或其他入口点触发

链：__wakeup() → clear() → sendResetMail() → file_put_contents()，$email完全可控。

限制：clear() 判断$_SESSION['LOGIN']，必须登录拿到 session才能触发。

三个值得记住的点

1. `doView` 读 `$_POST['file']` —— 我之前用 GET 测一直返回空，差点误判成"无回显/不成立"。参数位置错了，漏洞就"看起来不存在"。
2. `FILTER_VALIDATE_EMAIL` 不是安全边界：`#@qq.com` 同时满足"像邮箱"和 SQL 注释，校验型函数不能替代参数化查询。
3. PHAR 触发有版本差异：目标 PHP 7.3 的 `file_exists()` 就会反序列化 `metadata`；我本机 PHP 8.4 只有 `getMetadata()`才触发。不能拿本机行为判断目标，否则会误以为 PHAR 打不通。

小结

整条攻击链复盘：SQL 注入拿到账号密码 → 登录获取 session → CKFinder 上传伪装 png 的 PHAR 包 → POST 访问 a=view，phar:// 触发反序列化 → POP 链写入 cache.php → POST 访问 cache.php 执行系统命令 → 获取 www-data 权限，内网横向。

入口

只要参数能到 phar://，以下函数都可能成为入口：

实战里常见的组合：

  • 上传头像 + 后台 getimagesize($avatar)；
  • 文件下载 + file_exists($file)；
  • 文件删除 + unlink($path)；
  • 图片处理 + exif_read_data($img)。

即使函数不输出任何东西，反序列化也已经发生(盲触发)，副作用靠 POP 链完成（写文件、发请求、执行命令）。

序列化与反序列化基础概述在 PHP 中，变量、数组、对象是驻留在内存中的数据结构，内存数据在脚本执行结束后会自动销毁，无法直接持久化存储或者跨请求传输。 序列化（serialize）与反序列化（unserialize）就是 PHP 提供的一套数据持久化方案： 序列化：将内存中的复合数据（数组、对象等）转换成一段具有固定格式的字符串，这个字符串保留数据的类型、值、对象类名、属性信息，可以存入文件、缓存、数据库、Cookie。 反序列化：读取序列化字符串，按照格式解析，在内存中重新还原成原来的 PHP 变量、对象实例。 前提：序列化只能保存数据（属性），不能保存方法代码。反序列化还原对象时，要求当前运行环境中已经加载该对象对应的类定义，否则得到的是 __PHP_Incomplete_Class 不完整类对象，无法调用类内方法。 函数原型12string serialize(mixed $value)mixed unserialize(string $str, array $options = []) 支持序列化的数据类型：string、int、float、bool、null...
