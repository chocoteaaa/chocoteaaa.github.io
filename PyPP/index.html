Python原型链污染及GeekChallenge2023原题详细分析

发表于2026-11-13|更新于2026-11-16

有点浅，感觉一些底层细节仍需打磨

说到原型链污染，比较出名是Node.js、Python，但不是只有这两个，原型链污染本质不是语言专属漏洞，是「语言有可被外部控制的对象合并 / 递归赋值 + 对象存在特殊原型属性」才会出现。

而大家口中标准的「原型链污染」实际上是Node.js正统原型链污染这种，而其实Python是仿原型链污染，因为Python本身并没有像JavaScript那样显式的 “原型” 概念，这里的 “原型链污染” 更多是一种类比，其核心是利用Python对象继承链上的属性查找机制，实现非预期的属性覆盖或方法劫持，从而引发安全问题。一般会叫它 Python 类污染（Class Pollution），虽然我们很多地方叫他原型链污染，但底层机制和 JS 不一样。

简单来说，Python中每个对象的 __class__ 指向所属类，类的 __bases__ 指向父类，构成属性查找链。访问属性时解释器沿链向上搜索；原型污染就是攻击者往这条链的祖先注入恶意属性 / 方法，程序查找到被污染的值后，触发恶意代码。

原型污染之所以危险：程序在处理用户传入的 JSON、请求参数等不可信外部数据，用字典更新、深度合并把输入合并到内部对象时，如果没有校验拦截，攻击者就能用特殊键向上污染基类。后果包括篡改配置、泄露信息，甚至远程代码执行；在 Flask、Django 这类大量引用第三方库的 Web 应用里，攻击面很大。

原型链污染

在原型链（主JS）中每个对象都有一个原型，原型上定义了对象可以访问的属性和方法。当对象访问属性或方法时，会先在自身查找，如果找不到就会去原型链上的上级对象中查找。

Python原型链污染（Prototype Pollution）是一种通过修改对象原型链中的属性，导致程序行为偏离预期的攻击技术。

Python 原型链污染和 Node.js 原型链污染攻击表现相似，Node.js 通过控制键值修改实例的原型对象；Python 主要是篡改类属性。受限于输入一般只能传入 JSON 基础数据，实战中大多只能篡改普通属性，很难直接替换类方法。

Python的属性查找机制

在Python中，一切皆对象。每个对象都有一个 __dict__ 属性，用来存储它自己的属性和方法。当你访问 obj.attr 时，解释器首先会在 obj.__dict__（实例自己的字典）里找。

如果没找到，它不会立刻报错，而是会转向 obj.__class__ （即对象的类）的 __dict__ 里找（obj.__class__.__dict__（也就是 A.__dict__））。

如果还没找到，它会继续沿着类的继承关系（ A.__bases__ ）向上查找，直到顶层（通常是 object 类）。这个查找顺序，就是所谓的 “方法解析顺序”，可以通过 A.__mro__（继承链）查看。

完整真实流程还包含描述符逻辑，CTF学习可以简化理解为沿着MRO各个类的__dict__依次查找。

这个机制是实现继承和多态的基础。安全问题就藏在这个 “向上查找” 的过程里。若攻击者能够修改链上某个祖先类（比如 Grandpa ）的 __dict__ ，则所有继承自它的子孙对象，在访问某个属性时，都可能拿到被篡改后的值。

__slots__（防污染重点）

默认实例都有 __dict__，可以动态新增属性。 如果类写了 __slots__：

理解merge执行步骤:

主要还是理解题目代码，merge(payload, cat1) 在这里，我们自行控制的payload作为 src 传入 merge 函数，目标实例 cat1 作为 dst 传入，并且将 payload 对应的 k 和 v 的值取了出来。

先讲一下merge的执行步骤： 遍历 payload 第一次循环时： k = "__class__"，v = {"__dict__": {"is_admin": True}}

然后会检查 cat1 中是否有 __getitem__ 方法，因为 cat1 是类实例不是字典，所以返回为 false，进入 elif 判断，检查 cat1 中是否有 __class__ 属性和 v 是否为字典。因为 cat1 是对象类型，并且含有 __class__ 默认属性，并且 v 也为字典格式，故执行这条判断语句。

递归合并 merge(v, getattr(dst, k)) 的作用是将一个字典 v 的内容合并到目标对象 dst 的属性 k 中。getattr(dst, k) 用于获取 dst 对象中的属性 k。如果 k 是一个字符串，getattr 将返回 dst 对象中名为 k 的属性的值。

第一次递归

此时： src = {"__dict__": {"is_admin": True}} dst = Cat（cat1.class 就是 Cat 这个类本身）

第二次递归

循环里面： k = "__dict__"，v = {"is_admin": True}

检查dst（Cat）是否有 __getitem__，不满足；进入elif，检查Cat是否拥有属性 __dict__，同时 v 是字典，条件成立，继续递归。

此时： src = {"is_admin": True} dst = Cat.__dict__

第三次递归

循环里面： k = "is_admin"，v = True

检查 dst（Cat.dict），它是 mapping，有 __getitem__；判断 dst.get(k)，此时还没有 is_admin，条件不成立，走入 dst[k] = v，等价于往 Cat.__dict__ 里面写入 is_admin = True，递归结束。

到此简单的链污染已经完成。只要是Cat的实例，自身没有定义 is_admin，访问该属性时就会沿着属性查找链读到类上面被污染的 is_admin。所以 cat1、cat2 全部判定为管理员。

不是所有类都可以被污染：如果这个类设置了 __slots__，没有开放动态属性，或者目标魔法属性被拦截、只读，这条链路就走不通；想要污染成功，必须能够沿着这条属性访问链路抵达写入点，并且写入点允许赋值。

除修改属性之外，还可替换内容，如密钥什么的（flask）。

原因：FROM python 现在拉 3.13，MarkupSafe==1.1.1 没有 wheel，会编译失败；3.8 的 cp38 manylinux wheel齐全

此题核心考点：

  • Python 原型链污染（目标：注入 isvip=True）
  • 数字巧算绕过 num 的判断
  • WAF（waf()）拦截，需要绕 WAF
  • 也可 JSON unicode 转义绕过 WAF
  • 自定义递归 merge，就是我们前面一直在学的那一款漏洞合并函数
  • 路由逻辑：注册 → 登录 → /flag 拿 flag，两道关卡

一眼看到我们前面说的merge，代码就是一个登录逻辑。

关键对象：

  • User：父类，自带 isvip = False
  • hhh(User)：子类，注册的时候 user = hhh()，然后 merge(data, user)，这就是污染入口
  • merge 和我们之前练习的代码完全一致

根因在类定义

  • hhh 继承了 User，但重写 __init__ 时没有调用 super().__init__()，所以 hhh() 实例自己的 __dict__ 里没有 isvip。
  • Python 取属性顺序：实例 __dict__ → 类 → 父类 → …，一路找不到就 AttributeError。
  • /flag 里是 if user.isvip:（直接点属性，不是 getattr(user, 'isvip', False)），所以没污染时直接 500，不是 403。
  • 结论：正常注册的账号永远过不了第二关，必须把 isvip “造”出来。

这也是很多题的分水岭：代码期望这个属性存在，但实际没有。找到这种缺口，再想办法把它补上。

路由梳理

/register（漏洞入口）

  • 请求体必须是 JSON（Content-Type: application/json）。用表单的话 Flask 会把 body 吃掉，request.data 为空，json.loads 直接抛异常。
  • 顺序很关键：先 WAF，再 json.loads，最后 merge。WAF 看的是 “解析前的原始字节”，这就是后面能绕过的原因。
  • merge(data, user) 就是污染触发点；注册成功把对象塞进全局列表 registered_users。

/login

  • 收表单 username/password，在 registered_users 里匹配。
  • 命中后把两个值写进 session。session 是服务端用 app.secret_key 签名的 cookie。
  • /flag 拿着 session 里这两个值回查 registered_users，所以伪造 session 不能凭空造用户。

/flag（第二重关卡）

这一块的绕过写在后面的。

merge 怎么变成”任意属性写”

k 完全来自用户 JSON，没有白名单 —— 你给什么 key，它就拿去 getattr/setattr。

dst 是什么 走哪条分支
dict / Config（dict 子类） ① 先 dst[k]=v
普通对象（如 hhh() 实例） ②③ 有属性就下钻，没有就 setattr
类对象（如 User） ②③ 同理，类上也没有 isvip，所以 setattr(User,"isvip",True)

两个容易卡的判定：

  • type(v) == dict 是严格判断，所以每层都得写成嵌套 JSON 对象；最后的值写 true（bool）才会走 setattr。
  • ① 分支要求 dst.get(k) 是真值才下钻，目标值是 False/空串/空字典时会停止下钻、直接覆盖。

严格说这叫”递归合并污染 / 属性注入”，Python 没有 JS 的原型链，但效果类似，习惯上还叫”原型链污染”。

三条路径：只有两条有效

路径 1：直接写实例（最短）

  • 遍历到 isvip：实例上没这个属性 → setattr(user,"isvip",True)。
  • 只影响这一个用户，完全够通关。WAF 那里必须用转义（见第五节）。

路径 2：写父类 User（有效）

上面只是逻辑结构；实际发包时 isvip 必须转义成 "\u0069svip"，否则会被 WAF 拦（见第五节）。

执行链路：

  • k="__class__" → 拿到 hhh 类
  • k="__base__" → 拿到 User 类
  • k（解码后 isvip）→ User 上没有这个属性 → setattr(User,"isvip",True)

之后所有 hhh 实例（包括已经创建的）访问 .isvip 都是 True（属性在取的时候才查类）。

顺带：只写 {"__class__":{"isvip":true}} 也能过——把 isvip 挂到 hhh 类上，效果一样，少一层。

路径 3：走 __dict__（无效）

看上去链条更”底层”，但我实测返回 泰酷辣,没有注册成功捏，注册失败。原因：

类的 __dict__ 是 mappingproxy（只读视图）。merge 走到它时，hasattr(dst,'__getitem__') 为真，但 dst.get('isvip') 是 None，于是走 dst[k]=v，直接抛：

TypeError: 'mappingproxy' object does not support item assignment

异常被 except 吞掉，前端只看到”泰酷辣”。

记住：setattr(User, "x", 1) 可以，User.__dict__["x"] = 1 不行。能写类和能写类的 __dict__ 是两回事。

WAF 与绕过

  • 检查点：waf(request.data) 在 json.loads 之前执行。request.data 是 bytes，str() 之后形如 b'{"username":...}'，也就是原始报文。
  • 黑名单：isvip、_static_folder、os、loader、defaults、kwdefaults。全是 Flask 属性链的经典 gadget，作者明显在防”沿属性链打到底”，但漏掉了最朴素的”直接写实例属性”。
  • 绕过：JSON 支持 \uXXXX 转义，把键名 isvip 写成 "\u0069svip" 或全转义 "\u0069\u0073\u0076\u0069\u0070"。
    • WAF 只看到反斜杠和数字，放行；
    • json.loads 解析时还原成 isvip，送进 merge，属性照写。
  • 适用范围：这条只对”解析前查原始报文“的 WAF 有效。如果 WAF 是解析完 JSON 再遍历 key 检查，转义早被还原，就没用了。
  • 子串误伤：黑名单是朴素 in，os 只有两个字母。用户名/密码里带 os（比如 boss、carlos）也会被拦，实测 {"username":"boss",...} → fuck payload!Hacker!!!。所以 payload 里任何地方都别出现明文 isvip；__class__、__base__ 可以明文写。

num 绕过

条件 作用
'0' not in data 字符串层面不能含字符 0
data != "123456789" 不能直接抄答案
int(data) == 123456789 数值层面必须等于答案
len(data) <= 10 长度限制

矛盾点：字符串上不能等于答案、不能有 0；数值上又要等于答案。利用 int() 比字符串比较”宽容”：

  • int() 会去掉前后空白（空格、\t、\n）
  • int() 接受可选正负号 + / -
输入 长度 含 0 ≠ 字面量 int() 结果
123456789 9 否 否 123456789 被拦
123456789 （尾空格） 10 否 是 123456789 通过
+123456789 10 否 是 123456789 通过
0123456789 10 是 是 123456789 被拦

⚠️ 一个容易讲错的地方：URL 里裸 + 会被解码成空格。
发 ?num=+123456789，服务端拿到的是 " 123456789"（前导空格），不是 "+123456789"；
想真正发加号要写 %2B。三种写法实测都能过，但原因不同：

  • ?num=+123456789 → 前导空格
  • ?num=%2B123456789 → 真正的 +
  • ?num=123456789%20 → 尾部空格

  • WAF 查的是原始字节，payload 里不能出现明文 isvip；但 __class__、__base__ 可以明文。
  • 黑名单是子串匹配，用户名/密码含 os 也会被误伤。
  • num 不要给 123456789、不要含 0；长度最多 10。
  • URL 里裸 + 是空格，不是加号。
  • 报错要分清：fuck payload!Hacker!!! = WAF 拦；泰酷辣,没有注册成功捏 = 代码抛异常（JSON 少括号最常见，别都怪 WAF）。
  • registered_users 是内存里的全局列表，重启进程（或重启容器）就清空，之前注册的号全没了。
  • /flag 的 flag 来自环境变量 geek_flag，不复现时忘了传 -e 会渲染成 None。
  • 请求头必须是 Content-Type: application/json；用表单提交 request.data 为空，json.loads 直接炸。
  • 污染类（User/hhh）是进程级副作用：之后注册的所有用户都自带 isvip，直到进程重启。

进阶（可选）：这条链还能打多远

merge 能一路走到模块全局，不止改 isvip：

  • 实测 Python 3.8 / 3.14 上，bound method 都能直接 .__globals__（拿不到就试 __func__.__globals__）。
  • 覆盖 SECRET_KEY 后，就能自己伪造 session。Flask 的 session 只是签名，不是加密：base64(JSON).时间戳.HMAC，短内容直接 base64，长内容前面多一个点、里面是 zlib 压缩。
  • 但本题不需要伪造：/flag 要求 session 用户在 registered_users 里，而账号是你自己注册的、密码你知道，直接登录更简单。伪造只在”拿不到密码 / 冒充别人 / 往 session 塞额外字段”时才有意义。
  • 验证密钥是否被改，有个金丝雀技巧：拿改之前的有效 cookie 再请求，如果突然变”未登录”，说明密钥已经换了。

这类题的核心不是背 payload，而是三件事：找到缺失的属性、找到可控的写入点、看清 WAF 检查发生在哪一步。
