工具简介

Nmap 全称 Network Mapper（网络映射器），是开源免费、跨平台的网络探测与安全审计工具，外号 “诸神之眼”，是渗透测试、CTF、网络运维最经典的信息收集工具。

只允许扫描自己拥有授权的设备 / 靶场，未经授权扫描公网 IP 属于违法行为，违反《网络安全法》

并且乱用的话也很容易触发告警，关于使用 Nmap 的风险可简单分为四类：

  1. 法律风险：无授权扫描违反《网络安全法》《治安管理处罚法》，严重可触及刑法；
  2. 告警风险：SYN 扫描、异常标志位、高速发包、版本探测特征明显，容易被 IDS、WAF、云安全检测，触发告警甚至 IP 封禁；
  3. 业务风险：高速扫描、UDP 扫描、NSE 脚本可能导致老旧设备宕机、服务异常、日志占满磁盘；
  4. 溯源风险：默认暴露源 IP，逃逸参数有局限，流量和日志可溯源定位扫描者。

所以不要乱用

基础信息

  • 作者：Gordon Lyon（网名叫 Fyodor），1997 年首次发布，持续维护至今
  • 开发语言：C/C++、Lua、Python
  • 支持平台：Linux（Kali 自带）、Windows、macOS、BSD
  • 协议：NPSL（Nmap 开源协议），可自由修改、非商用分发；商用嵌入需要单独授权
  • 官网：https://nmap.org

Nmap 套件（不止 nmap 本体）

  1. nmap：核心命令行扫描程序（我们平时用最多）
  2. Zenmap：官方图形化 GUI，可视化扫描、看结果
  3. Ncat：升级版 nc，端口转发、连接监听、数据传输
  4. Ndiff：对比两次扫描结果，发现新增开放端口、主机变化
  5. Nping：数据包发送工具，自定义 TCP/UDP/ICMP 包，类似高级 ping

核心原理

主动向目标发送自定义原始 IP 数据包，分析目标返回报文，推断网络状态.

它不是简单 ping，它可以构造 SYN、FIN、ACK、UDP 等各种 TCP 标志位包，根据不同响应判断端口状态。

比如 SYN 扫描：发 SYN 包 → 收到 SYN+ACK → 判断端口 open；收到 RST → 判断 closed；无响应 → filtered。

五大核心能力（本文主要内容）

  1. 主机发现（存活探测） 判断网段里哪些机器开机、在线。不止 ICMP ping，还支持 TCP Ping、ARP Ping、UDP Ping；很多防火墙禁 ping，Nmap 依然可以探测存活主机。
  2. 端口扫描（最核心） 探测 TCP/UDP 端口，输出 6 种端口状态：open /closed/filtered /unfiltered/open|filtered /closed|filtered。 支持十多种扫描方式：SYN 半开扫描、Connect 全连接、UDP 扫描、FIN/Xmas/Null 隐蔽扫描等。
  3. 服务版本识别（-sV） 端口开放后，发送探测报文，匹配内置特征库，识别端口上跑的服务、版本号（OpenSSH、Apache、MySQL、Samba 等），版本是后续找漏洞的关键。
  4. 操作系统指纹识别（-O） 根据 TCP/IP 栈指纹特征，猜测目标是 Windows、Linux、路由器、摄像头等设备和系统版本，不一定百分百准确。
  5. NSE 脚本引擎（Nmap Scripting Engine，Lua 脚本） Nmap 最强扩展点，内置几百个 Lua 脚本，直接做：漏洞检测、弱口令爆破、信息抓取、服务枚举。 脚本分类：vuln 漏洞扫描、brute 暴力破解、discovery 信息搜集、safe 安全探测、auth 认证检测等。 示例：smb-vuln-ms17-010（永恒之蓝）、http-title、ftp-brute

优缺点

优点

  • 免费开源，跨平台，Kali 默认自带
  • 扫描类型丰富，适配各种防火墙环境
  • NSE 脚本生态极强，可自定义脚本
  • 输出格式丰富（文本、XML），可以导入 Metasploit、Nessus 联动
  • 支持超大网段批量扫描，速度可控

缺点

  • UDP 扫描极慢（UDP 无确认机制）
  • OS 识别依赖指纹库，容易误判，云服务器、加固设备识别不准
  • 隐蔽扫描（SYN、FIN）在 Linux 需要 root 权限；Windows 需要管理员权限
  • 扫描流量容易被 IDS / 防火墙告警、封禁 IP
  • 它只是信息收集工具，不是漏洞利用工具，只能发现，不能直接拿权限

核心能力利用

使用版本为 nmap 7.95 版本，nmap有五大核心能力,本文重点总结四种基本功能：「端口扫描」、「主机探测」、「服务识别」、「系统识别」，第五点作为扩展点，仅提一提。

总语法

目标可以是：IP、域名、CIDR（192.168.1.0/24）、范围（10.0.0.1-50）、-iL hosts.txt（文件输入）。

所有板块都套它

整体流程

-sn 探测存活主机 → -sS/-sU 枚举开放端口 → -sV 识别服务与版本 → -O 探测操作系统；时序参数控制扫描速度，-oA 导出扫描结果留存证据。

主机探测（Host Discovery）

目的：在大网段里先找出“活着的主机”，再对活主机做端口扫描。这是省时间的第一步，不是可选项。-sn 代表仅探活，不执行端口扫描

基础命令

命令 作用
nmap -sn 192.168.1.0/24 只做主机发现，不扫描端口（旧参数 -sP 已废弃）
nmap -sL 192.168.1.0/24 列表扫描，不发包，仅 DNS 反解，列出目标范围
nmap 192.168.1.10 默认行为：先探活，主机存活后扫描默认 Top1000 端口
nmap -Pn 192.168.1.10 跳过主机探测，默认主机在线，直接扫描（防火墙禁 ping 必用，旧参数 -P0）

指定探测方式（可组合，任意一种探测收到响应即判定主机存活）

参数 探测类型 默认端口 说明
-PS22,80,443 TCP SYN ping 80 收到 SYN+ACK/RST 都判定存活，穿透性最好
-PA80,443 TCP ACK ping 80 绕过只拦截 SYN 包的防火墙
-PU53,161 UDP ping 40125 发送 UDP 包，收到 ICMP 不可达即判定存活
-PE ICMP Echo Ping — 传统 ping，极易被防火墙拦截
-PP ICMP Timestamp Ping — 绕过禁止 Echo 的主机
-PM ICMP Address Mask Ping — 老旧系统才会响应，使用较少
-PO1,6,17 IP 协议 Ping — 按 IP 协议号探测，冷门场景使用
-PR ARP Ping — 同网段默认启用，速度最快准确率最高，不能跨路由器

配套辅助参数

参数 作用
-n 不做 DNS 反解析，大网段扫描提速首选
-R 强制对所有目标执行 DNS 反解
--dns-servers 8.8.8.8 指定自定义 DNS 服务器
--reason 输出主机存活判定依据（收到哪种回包），排查误判
--traceroute 同步路由追踪，查看网络跳数
--discovery-ignore-rst 7.9 + 版本新增，忽略 RST 包作为存活依据，减少误报
--min-rate / --max-rate 控制探测发包速率

关键概念：主机发现和端口扫描是两个独立阶段。-sn 之后接 -Pn 没意义（-sn 本身就不扫端口）；-Pn 之后 nmap 不会再做任何探活。

端口扫描（Port Scanning）

目的：在活主机上枚举开放的 TCP/UDP 端口。判断端口状态（open /closed/filtered /unfiltered/open|filtered /closed|filtered）

端口范围写法

写法 含义
-p 80 单个端口
-p 1-1000 连续端口范围
-p- 全端口 1-65535
-p 22,80,443,8000-8100 离散端口 + 范围混合
-p U:53,T:80 指定协议，区分 UDP/TCP 端口
-p http,https 使用 /etc/services 内服务名扫描
-F 快速扫描，仅 Top100 端口
--top-ports 1000 扫描指定数量热门端口，默认 1000
--port-ratio 0.5 按服务流行度比例筛选端口
--exclude-ports 22,3389 排除指定端口不扫描

扫描类型（核心，多数需要 root/sudo 权限）

参数 扫描类型 原理 & 适用场景
-sS SYN 半开扫描 只发 SYN 包，收到 SYN+ACK 判定 open，不完成三次握手；root 默认扫描方式，隐蔽、速度快，首选
-sT TCP Connect 全连接扫描 完整三次握手；无 root 权限时自动降级为此扫描，会在目标留下连接日志
-sU UDP 扫描 扫描 DNS/SNMP/NTP 等 UDP 服务；扫描速度极慢，务必搭配--top-ports限制端口
-sA ACK 扫描 无法判断端口开闭，仅用于判断防火墙是否过滤端口，结果只有 unfiltered/filtered
-sW Window 窗口扫描 基于 TCP 窗口大小判断端口状态，仅部分老旧系统生效
-sN/-sF/-sX NULL/FIN/XMAS 扫描 发送异常 TCP 标志位，尝试绕过无状态防火墙；Windows 系统全部回 RST，结果全部 closed，不要对 Windows 使用
-sM Maimon 扫描 FIN+ACK 组合包，极少使用
--scanflags SYNFIN 自定义 TCP 标志位扫描 可自定义 TCP flags，也支持十六进制--scanflags 0x3F
-sI <僵尸主机> Idle 空闲扫描 借助第三方空闲主机 IPID 做扫描，隐藏源 IP；需要一台 IPID 可预测的空闲主机
-sO IP 协议扫描 枚举目标支持的 IP 协议（TCP/UDP/ICMP/GRE 等），不扫描端口
-sY/-sZ SCTP INIT / COOKIE-ECHO SCTP 协议扫描，电信信令场景专用

性能速率进阶参数

参数 作用
-T0 ~ -T5 时序模板：T0 偏执、T1 诡秘、T2 礼貌、T3 默认、T4 激进（常用）、T5 疯狂
--min-rate 500 最低发包速率，提速
--max-rate 1000 最高发包速率，限速规避告警
--min-parallelism / --max-parallelism 控制并行探测数量
--min-hostgroup / --max-hostgroup 控制同时扫描的主机数量
--max-retries 1 最大重传次数，数值越小速度越快，漏报风险升高
--host-timeout 5m 单台主机扫描超时，跳过卡死目标
--scan-delay 1s 每个探测包之间延迟，用于隐蔽扫描
--max-scan-delay 延迟上限
--min-rtt-timeout / --max-rtt-timeout / --initial-rtt-timeout RTT 超时，高延迟网络调大数值
--defeat-rst-ratelimit 对抗目标 RST 限速，避免端口误判为 filtered
--defeat-icmp-ratelimit 对抗 ICMP 限速

速率策略示例：

伪装 / 逃逸参数（高风险，极易触发告警）

参数 作用
-D RND:10 生成 10 个随机诱饵 IP 混淆溯源
-D 1.2.3.4,5.6.7.8,ME 指定诱饵 IP，ME 代表本机真实 IP
--spoof-mac 0 / --spoof-mac Cisco 伪造 MAC 地址，仅同网段生效
--data-length 50 数据包附加随机填充数据，改变包特征
-g 53 / --source-port 53 伪造源端口，绕过仅放行指定源端口的 ACL
--badsum 发送错误校验和，探测中间网络设备
--send-ip / --send-eth 指定三层 IP 发包 / 二层以太网发包
-e eth0 指定扫描网卡
-S <源IP> 伪造源 IP，需要路由配合
--randomize-hosts 打乱主机扫描顺序

解读提示：-sA 结果 unfiltered ≠ 端口开放，仅代表端口没有被防火墙拦截，端口是否开放需要 SYN 扫描验证

服务识别（Service / Version Detection）

作用：从 “端口开放” 进一步识别端口上运行的服务、版本，用来匹配 CVE 漏洞

基础命令

命令 作用
nmap -sV 10.0.0.5 开启版本探测，发送探针比对指纹库
nmap -sV -p 22,80,443 10.0.0.5 仅对指定端口探测版本
nmap -sV --version-light 10.0.0.5 轻量探测，强度 = 2，速度快，识别不全
nmap -sV --version-all 10.0.0.5 全强度探测，强度 = 9，最慢，识别最完整
nmap -sV --version-intensity 5 自定义探测强度 0~9，默认 7；0 仅依靠端口猜服务名，不发探针
nmap -sV --version-trace 10.0.0.5 打印探针交互过程，调试排错
nmap -sV --allports 10.0.0.5 取消默认排除（打印机 9100 端口），全部端口执行版本探测

进阶用法

参数 说明
-sV --script=banner 抓取服务 banner，补充版本信息
-sV --script=http-title,http-headers Web 服务提取网页标题、响应头
-A 激进扫描全家桶 = -O -sV -sC --traceroute
--script-updatedb 更新 NSE 脚本库
--script-help <脚本名> 查看脚本使用文档

识别结果坑点

  1. tcpwrapped：三次握手完成后直接断开，端口被 ACL / 负载均衡拦截，服务不可用
  2. unknown：探针无法匹配指纹，服务修改 banner，需要--version-all重试
  3. ssl/http：端口跑 HTTPS，后续需要按 TLS 服务处理
  4. 版本探测会发送应用层探针，会在目标日志留下记录，大批量扫描前评估告警风险

系统识别（OS Detection）

作用：依靠 TCP/IP 协议栈指纹，推断目标操作系统类型与版本；需要 root 权限

基础命令

命令 作用
nmap -O 10.0.0.5 开启操作系统指纹识别
nmap -O --osscan-limit 10.0.0.5 仅对识别成功率高的主机探测，节省时间
nmap -O --osscan-guess 10.0.0.5 积极猜测，输出多个低置信候选系统
nmap -O --max-os-tries 2 10.0.0.5 限制 OS 探测重试次数
nmap -A 10.0.0.5 内置 -O，同时包含版本、脚本、路由追踪

前置硬性条件（识别失败最常见原因）

-O 要求目标至少存在 1 个 open 端口 + 1 个 closed 端口；如果端口全部 filtered 或者全部 open，Nmap 会输出警告，识别结果不可信

解决办法：

结果解读

  • OS details：高置信度系统结论
  • Aggressive OS guesses：低置信猜测，不能作为报告结论
  • Network Distance：路由跳数，辅助判断是否经过 NAT、代理

无 -O 辅助判断系统的方式

手段 说明
nmap -sV --script=banner SSH、FTP 等 banner 经常携带系统发行版信息
TTL 粗略判断 Linux 默认 64，Windows 默认 128，网络设备 (路由 / 摄像头) 常为 255
端口扫描行为 Windows 对 FIN/NULL/XMAS 扫描统一回 RST；Linux 不响应
--script=ssl-cert SSL 证书内有时包含主机名、系统信息

-O 需要 root/raw socket 权限；非 root 会直接报错。

实战场景模板

场景 命令
快速摸底 nmap -T4 -F --open 10.0.0.5
标准普查（渗透常用） nmap -sS -sV -sC -Pn --open 10.0.0.5
全量详细扫描（报告用） nmap -sS -sV -sC -O -Pn -p- --open --reason 10.0.0.5 -oA full
内网快速全端口 nmap -sS -Pn -n -p- --min-rate 2000 -T4 10.0.0.5
UDP 抽查 nmap -sU --top-ports 50 --max-retries 1 10.0.0.5
网段主机存活探测 nmap -sn -PS22,80,443 -PA80,443 -n 10.0.0.0/24
防火墙规则探测 nmap -sA -p 1-1000 10.0.0.5
隐蔽慢扫 nmap -sS -T1 --scan-delay 2s --max-rate 50 -D RND:5 -p 22,80,443 10.0.0.5
服务细查 nmap -sV --version-all --script=banner,http-title 10.0.0.5

输出 & 调试参数

参数 作用
-oN out.txt 普通文本格式
-oX out.xml XML 格式，可导入 Metasploit、Nessus
-oG out.gnmap grep 友好格式，方便 shell 处理
-oA out 一次性输出三种格式（推荐）
--open 只展示 open 端口，会丢失 filtered 信息
-v / -vv 详细输出，vv 信息更多
-d / -d9 debug 调试级别，排错使用
--packet-trace 逐包打印，验证数据包是否被拦截
--resume out.gnmap 断点续扫，扫描中断后恢复

高频坑汇总

  • -sn 跨网段不使用 ARP：ARP 仅同网段生效；跨路由会退回 ICMP/TCP 探测，禁 ping 网段容易漏存活主机
  • 权限限制：-sS/-O/-sI 需要 raw socket，普通用户自动降级为 -sT，OS 识别直接失败，必须 sudo
  • UDP 扫描禁止全端口：-p-扫 UDP 极慢，务必加--top-ports
  • OS 识别依赖端口样本：缺少 closed 端口，识别结果不可靠
  • FIN/NULL/XMAS 扫描对 Windows 无效，结果全部 closed，容易误判
  • -T5疯狂模式极易丢包，RST 丢失会把开放端口误判 filtered，优先 T4
  • --open过滤掉 filtered 状态，需要分析防火墙策略时不要加
  • RST 限速造成假 filtered：降速或者添加--defeat-rst-ratelimit
  • -A流量噪音大，探针 + 脚本多，容易触发告警，生产环境建议拆分参数分步扫描
  • -sV/-sC的应用探针会留下日志，大批量扫描前评估风险

CTFShow内网渗透Web859

我们这次主要是借助这个题目来测试Nmap。

开启环境后根据提示，首先这是一个需要本地 SSH 连接的靶场，我们连上即可。

还有一个重要的提示即：攻击机不出网。

环境准备（先解决没有 nmap 的问题）

SSH 进去后发现：

1、攻击机是 Ubuntu 20.04 容器

  • 攻击机由：cat /etc/os-release输出得来（/etc/os-release描述的是用户态镜像版本）
  • 同时 uname -a 返回：

提一提为何要总结方法，因为传fscan工具仅需一条scp命令，觉得原来的方法有点麻烦

fscan 和 nmap 的形态差异

fscan 本机 Kali 的 nmap 7.95
文件形态 单个 静态 Go 二进制 动态 ELF + 一堆 .so + /usr/share/nmap 数据
依赖 无 loader /libc/libssl /liblua… + nmap-services、nmap-os-db、nse 脚本
一条 scp 够不够 够，传完 chmod +x 就能跑 二进制能传上去，但 -sV/-O/NSE 会因缺数据文件而残废

所以 nmap 的最简等价物不是“一个二进制”，而是一个 tar 包。上传可简化成和fscan那条 scp 一样的一行

  • 像fscan一条scp在上传层面可以做到：scp -P 28219 nmapbundle.tgz ctfshow@...:/tmp/
  • 但nmap不是单文件程序，后面必须跟一条解包/运行命令；真正压到一条ssh就用方案 B
  • 只传/usr/lib/nmap/nmap 那一个二进制是不够的：没有/usr/share/nmap，-sV无探针库、-O无指纹库、--top-ports无端口表
