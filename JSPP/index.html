JS原型链污染（及CVE‑2022‑29078）及与Py的区别

发表于2026-11-16|更新于2026-11-16
|总字数:6105|阅读时长:24 分钟|浏览量:

JS原型链污染指的是JavaScript原型链污染，是JavaScript语言特性带来的安全缺陷，不是 Node.js发明或专属的。常和Node.js联系在一起的原因是涉及Node.js后端场景时危害被放大，且攻击面更典型

Node.js并没有“制造”原型链污染，它只是提供了更多接收不可信输入并对其进行对象操作的机会，同时运行在服务端意味着一旦被利用，影响范围更大（所有请求共享同一个运行时原型）。

维度 JavaScript Node.js
本质 一种编程语言（ECMAScript 规范的实现） 一个运行时环境（runtime）
作用 定义语法、数据类型、逻辑写法 提供让 JS 在浏览器之外运行的能力
依赖 需要宿主环境才能执行 本身就是宿主环境

核心机制

在JavaScript中，几乎所有的对象都继承自Object.prototype。当你访问一个对象上不存在的属性时，引擎会沿着原型链向上查找，最终到达Object.prototype。

其实看了Python的也知道大概思路，因此，原型链污染的攻击路径通常是：

  • 应用代码存在“不安全地合并/克隆用户输入对象”或“按路径设置对象属性”的逻辑。
  • 攻击者构造包含 __proto__ 或 constructor.prototype 键的恶意输入（常见于 JSON 请求体）。
  • 代码在赋值时，意外地沿着这个特殊键访问到了 Object.prototype，并在其上添加或修改了属性。
  • 此后，该运行时中所有新建的普通对象都会“继承”到这个被污染的属性，即使它们与攻击者的输入毫无直接关系。

根据 OWASP 的分类，这可能进一步导致拒绝服务、认证绕过、权限提升，甚至在 Node.js 环境中触发远程代码执行。

__proto__

通过Foo.prototype来访问Foo类的原型，但Foo实例化出来的对象，是不能通过prototype访问原型的，这时候，需要用到__proto__了。

一个Foo类实例化出来的foo对象，可以通过foo.__proto__属性来访问Foo类的原型，也就是说：

  • 一个对象的__proto__属性，指向这个对象所在的类的prototype属性
  • 每个对象都有一个名为__proto__的内置属性，它指向该对象的原型，每个函数/类也都有一个名为 prototype 的属性，它指向该函数或类的原型
  • 当一个类实例化后会用于prototype中所有的属性和方法

原型&原型链

几乎所有的对象都有一个隐秘的链接 ，指向另一个称为其 “原型” （prototype）的对象。当你试图访问一个对象的属性时，如果这个对象自身没有该属性，JavaScript引擎就会沿着这个链接去它的原型对象上找，如果原型对象上也没有，就继续去原型的原型上找，直到找到属性或者到达链条的尽头（ null ）。这条由原型对象连接起来的路径，就是 原型链 。

关于这一块可参考：继承与原型链 - JavaScript | MDN

每个对象都有内部原型

  • 普通对象通过 [[Prototype]] 指向另一个对象，访问器是 __proto__（历史遗留，但真实存在）。
  • 函数有 prototype 属性，指向一个对象，这个对象会成为该函数构造出的实例的原型。
  • 构造器函数本身也有 [[Prototype]]，通常指向 Function.prototype。

链的终点是 Object.prototype

Object.prototype 是绝大多数普通对象共享的同一个对象。改它，等于改所有对象的默认行为。

原型链继承

所有类对象在实例化的时候将会拥有prototype中的属性和方法，这个特性被用来实现JavaScript中的继承机制。即当一个对象试图访问一个属性或方法时，如果在该对象自身没有找到，JavaScript会沿着原型链向上查找，直到找到对应的属性或方法，或者达到原型链的顶端 null 为止。

我们让Son的原型为Father对象实例，则Son类会继承Father类所有属性和方法，所以会输出Father类的姓john

而输出儿子名字并没有变，从继承机制可知，在Son类找得到这个属性，所以不会再顺着原型链往上找。

总结一下，对于对象son，在调用son.last_name的时候，实际上JavaScript引擎会进行如下操作：

  • 在对象son中寻找last_name
  • 如果找不到，则在son.__proto__中寻找last_name
  • 如果仍然找不到，则继续在son.__proto__.__proto__中寻找last_name
  • 依次寻找，直到找到null结束。比如，Object.prototype的__proto__就是null

JavaScript的这个查找的机制，被运用在面向对象的继承中，被称作prototype继承链。

以上就是最基础的JavaScript面向对象编程，我们并不深入研究更细节的内容，只要牢记以下几点即可：

  1. 每个构造函数(constructor)都有一个原型对象(prototype)
  2. 对象的__proto__属性，指向类的原型对象prototype
  3. JavaScript使用prototype链实现继承机制

原型链污染

前面__proto__二级标题说，Foo类实例化出来的foo对象，可以通过foo.__proto__属性来访问Foo类的原型Foo.prototype。

那么因为对象的__proto__属性，指向类的原型对象prototype，如果我们修改了foo.__proto__中的值，是不是就可以修改Foo类呢？

修改的是什么

  • foo.__proto__指向的是Object.prototype，不是Object这个类（构造函数本身）；
  • 修改foo.__proto__，是修改原型对象，不是修改构造函数 Object；
  • 所有以Object.prototype为原型的普通对象，都会共享这个原型上新增 / 修改的属性，这正是 JS 原型链污染的根源。

最后，虽然zoo是一个空对象{}，但zoo.bar的执行结果是2，这就说明链已经被污染了

修改了foo的原型foo.__proto__.bar = 2，而foo是一个Object类的实例，所以实际上是修改了Object这个类，给这个类增加了一个属性bar，值为2。

后来，我们又用Object类创建了一个zoo对象let zoo = {}，zoo对象自然也有一个bar属性了。

那么，在一个应用中，如果攻击者控制并修改了一个对象的原型，那么将可以影响所有和这个对象来自同一个类、父祖类的对象。这种攻击方式就是原型链污染。

修改的是什么

  • foo.__proto__ 指向 Foo.prototype，不是构造函数 Foo 本身；
  • foo.__proto__.msg = "polluted" 修改的是【原型对象】，不是直接修改 Foo；
  • 所有通过 new Foo() 创建出来、并且自身没有 msg 属性的实例，都会共享这个原型上的属性；以 Object.prototype 为原型的普通对象不受这次修改影响。

最后，虽然 bar 是全新 new Foo() 出来的实例，没有自己定义 msg，但是访问 bar.msg 拿到了污染后的值，说明 Foo 的原型对象被污染。

修改 foo.__proto__.msg，而 foo 是 Foo 的实例，所以实际上修改了 Foo 的原型对象，给这个原型对象覆盖了属性 msg。 之后只要再用 Foo 创建实例，实例在自身找不到 msg 时，就会读到被污染的值。

那么，如果在应用里，攻击者可控输入，可以往 __proto__ 写入属性，就可以污染这个构造函数对应的原型对象，影响所有该构造函数的实例，这就是 NodeJS 原型链污染最典型的一类场景。

污染条件

根据上述分析，原型链能被攻击者修改，其实就是我们可以设置__proto__的值，其实也就是找能够控制数组（对象）的“键名”的操作即可，离别歌给出了以下两点

  • 对象merge
  • 对象clone（其实内核就是将待操作的对象merge到一个空对象中）

其实包括上篇文章我们也可以知道，merge（深度合并）这个函数的作用就是把两个对象的内容融合在一起，把源对象的属性拷贝到目标对象，嵌套对象也跟着递归合并，而不是直接覆盖。

如果该函数配置处理不当就会造成安全问题，该函数也是 CTF 或者实际应用常见的特征点。

逐行解读

merge 函数

它的作用是把 source 的内容深度合并进 target。遍历 source 的每一个键：

  • 如果这个键对应的值是对象，就在目标上新建一个空对象，继续递归合并；
  • 如果是普通值，直接执行 target[key] = source[key]。
  • 致命点：没有任何针对 __proto__、constructor 的过滤。

payload 解析

JSON.parse 解析出来的对象，里面有一个键名字就是字符串 __proto__。
这里很关键：在 JS 里，当你做 obj["__proto__"] = xxx，不是往 obj 上增加一个叫 __proto__ 的普通属性，而是修改这个对象的隐式原型。

visitor 是全新创建的普通对象，它自己身上根本没有 isAdmin。按照 JS 属性查找规则，找不到就沿着原型链往上，一直查到Object.prototype，读到我们刚刚塞进去的 true。

核心原理

JavaScript对象访问属性的时候：

  • 先查对象自身的属性；
  • 如果找不到，就去它的原型对象；
  • 一路向上，直到原型为 null；
  • Object.prototype是绝大多数普通对象的顶层原型。一旦我们往它上面写入属性，所有普通对象都会共享这个属性。

这就是原型链污染：不是篡改某个单独对象，而是篡改原型对象，批量影响一大批对象。

补充小坑： 如果对象自己本身就有 isAdmin，会优先读自身，原型上的值不会生效； 如果是 Object.create(null) 创建出来的对象，没有原型，不受影响。

成功所需条件

  • 输入的 key 可控：攻击者可以自己指定键名，能够送入 __proto__、constructor、constructor.prototype；只能控制值、key 固定的话，没法打。
  • 存在无过滤的动态写入（sink）：递归合并、深拷贝、动态路径赋值，遇到特殊键不会跳过。经典的除了手写 merge，旧版 lodash 的 _.merge、_.set 都是。
  • 解析不会吃掉特殊键：JSON.parse 可以保留 __proto__；如果后端提前过滤、删除这个键，攻击链断掉。
  • 存在读取点（gadget）：光污染原型没用，后端代码必须有地方读取这个属性。比如权限判断 if(user.isAdmin)，只有代码读到它，才能实现越权、RCE 这类效果。

不成立情况:

  • 合并函数检测到 __proto__，直接跳过；
  • 使用 Object.create(null) 作为合并目标；
  • 只是浅层合并，不递归；
  • 目标原型上该属性被设置为不可写。

merge操作是最常见可能控制键名的操作，也最能被原型链攻击，很多常见的库都存在这个问题。

CVE‑2022‑29078

第一次遇见来自 CTFShow-Web341，不过这道 CTF 是原型链污染 + EJS 组合打出 RCE 的链子，而 CVE 指的是后者的EJS，以原型链污染为入口，标题写 CVE 要高级些，这里就用题目源码分析。

所以这里提一下非常关键的区分：

  • CVE-2022-29078 的本体是 EJS 引擎侧的 SSTI/RCE：renderFile 会把 options 里的 outputFunctionName、escapeFunction 等直接拼进编译源码，影响 ejs <= 3.1.6，3.1.7 修复（增加合法标识符校验、不再从原型链取这些选项）。本项目的 package-lock.json 恰好锁死 3.1.5，属于受影响版本。
  • 本题的入口不是 CVE 本身，而是 utils.copy 的原型链污染（应用自身的代码缺陷）。整条链是：原型链污染（入口，非 CVE）→ 污染 Object.prototype.outputFunctionName → 命中 CVE-2022-29078 的 sink → RCE。

所以严格表述是：web341 = 原型链污染 + CVE-2022-29078 组合利用，而不是”仅靠 CVE-2022-29078 就能打”。差异也体现在修复上：只升级 EJS 到 3.1.7+ 能堵住 sink（本题即失效），但 copy 的原型链污染本身仍需单独修。

操作陷阱

1、一个容器只有一次污染机会：Object.prototype.outputFunctionName 变成字符串后，再 POST 会走 copy("旧值","新值") → '0' in "旧值" 抛 TypeError → 500，且旧 payload 无法覆盖。要换 payload 必须重启容器/环境。

3、每次 GET / 都会重新编译并执行一次命令（视图无缓存），所以同一条 payload 完了可以重复读 flag，不用重新污染。

4、污染过程中，返回”登录失败”是正常的（isAdmin 是自身 false 遮蔽原型），不代表污染失败。

Py和JS污染区别

因为学长面试被问到这道题了，所以我自己也来总结一下：

JS vs Python

JS 是真正的原型继承污染（Prototype Pollution），修改共享原型对象，全局继承生效；Python 没有原型机制，CTF 里叫它 “原型链污染” 只是习惯叫法，本质是【类属性污染 / 属性路径覆盖】，依靠 MRO 继承链或者属性路径修改共享对象，必须有特殊 sink 才能触发。

这其实就是我上篇文章的总结。

对象模型对比

对比项 JavaScript Python
属性查找链路 实例 → [[Prototype]]（__proto__）→ … → Object.prototype 实例__dict__ → type(obj)（所属类）→ MRO（类→基类）
共享载体 原型对象，所有同类对象默认共享 类属性，该类、子类的全部实例共享
根节点 Object.prototype，默认可写 顶层object不可修改，赋值直接抛TypeError
内置类型 Array.prototype等内置原型可被污染 int/str/list等内置类型不可修改，只能污染用户自定义类、框架普通类
__proto__含义 Object.prototype上的访问器，具备特殊原型语义 无特殊魔法含义，仅仅是普通字符串 key
dict / 对象命名空间 obj.x 和 obj["x"] 是同一套空间 字典 key 和对象属性是两套独立空间：{"__proto__":{}}只是普通 dict 键，getattr拿不到

污染入口（Sink）差异

JavaScript

  1. 天然污染源多：JSON.parse解析后__proto__会成为自有属性，for...in、key in obj可以识别到这个 key，递归合并很容易触发污染
  2. 常见危险代码：不安全merge/extend/copy递归函数；经典库：lodash、dot-prop
  3. payload 核心 key：__proto__、constructor.prototype

例（web341 EJS 那道，两层 proto）：{"__proto__":{"__proto__":{"outputFunctionName":"payload"}}}

Python

  1. 原生json.loads输出普通 dict，{"__proto__":xxx}本身无害，不会自动污染
  2. 必须代码显式把 key 当成对象属性写入，才会形成污染：
    • setattr(obj,key,val)
    • 递归 merge：搭配getattr逐层取属性、递归赋值
    • **kwargs批量赋值、配置加载器、ORM 批量赋值
  3. 常用属性链：__class__、__base__、__bases__，进阶还可以走__globals__去修改全局 / 单例（比如 Flask 的 app.config）

注意：__globals__这条属于属性路径劫持，不属于继承链污染

影响面、利用方式对比

对比项 JavaScript Python
影响范围 进程级全局污染，几乎所有读取配置、options 的库都可以作为 gadget 只影响目标类、子类或者目标共享单例；范围由 MRO 或者目标对象决定
经典利用链 EJS outputFunctionName RCE、child_process 环境注入、模板引擎 gadget 修改isvip权限绕过；篡改app.config.SECRET_KEY伪造 session；配合 SSTI 的__globals__链（不属于原型污染）
通用性 通用原语，一次污染，大量第三方库可利用 强依赖题目里的 sink 代码，没有通用根原型可以污染
生效周期 进程生命周期内全局生效，需要delete清除；部分场景无法二次覆盖 类属性同样进程级生效；多 worker 模式下，仅当前 fork 进程受影响
标准名称 Prototype Pollution，大量独立 CVE（lodash、ejs 等） 标准叫法：类属性污染 / 属性注入，很少单独分配 CVE

审计识别要点

  • JS：检索merge/extend/copy、for...in递归、key in obj；注意判断原型层数，层数不对 payload 打不中目标 gadget
  • Python：检索setattr(、getattr(递归、手写 merge、**kwargs；重点判断目标是不是共享对象：类、app.config、全局注册器；单纯 dict update 不会触发污染

共通点 & 总结

共同点：

污染本质都是写入共享状态；单纯污染本身没有危害，必须找到下游 gadget 读取被篡改的属性，才能实现权限绕过、RCE 等效果；同一次污染对同一个进程内所有请求生效。

核心区分记忆

JS：篡改原型继承规则，所有对象自动继承被修改的属性
Python：没有原型，只是顺着类继承链 / 属性路径，修改类、全局单例上的属性

做题避坑：不要直接把 JS 的__proto__payload 思路套 Python；Python 优先__class__+__base__，且必须存在 setattr 类 sink。
