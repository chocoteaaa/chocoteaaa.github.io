CC1-LazyMap

我们知道 CC1 链的主要问题是InvokerTransformer这个类，里面的transform方法实现了任意方法调用写法，颇似一个后门的写法。

那么我们在对transform这个方法查找用法时，在org.apache.commons.collections.map里面我们发现有LazyMap和TransformedMap这两个，当时利用了后者，现在来讲前者。

AnnotationInvocationHandler

直接找的话非常之多，所以我们按经验，直接进AnnotationInvocationHandler类里面看，找那个invoke方法，有一个定义出来的字段调用了get方法，源码如下：

可见这个类是一个名为InvocationHandler的接口的实现类，这个接口是我们在动态代理的时候要用的一个接口

那么我们怎么进入invoke这个方法呢？这个方法只要在我们配置好动态代理后，调用动态代理配置对象的任何方法的时候，就会自动走到invoke这个方法里面。

是不是有点像上篇文章只要对memberValues传入transformMap后进行遍历就会自动走到MapEntry从而调用parent.checkSetValue😆😆

那么在反序列化的时候，只要将memberValues控制成LazyMap就行了，然后调用LazyMap的任意方法的时候，然后就会进入到这个invoke方法里面。

所以完整调用链（传入序列化链后）：

所以说人话就是，反序列化的时候进入了AnnotationInvocationHandler.readObject()方法：

  • 执行 s.defaultReadObject() 把成员变量读出来，其中 memberValues 就是我们构造好的动态代理 Map（proxyMap）；
  • 循环遍历 memberValues.entrySet()，调用代理 Map 的 entrySet()；
  • 因为是动态代理对象，JDK 自动拦截，进入内层 AnnotationInvocationHandler 的 invoke()；
  • 内层 invoke 里的注解相关逻辑，会调用 LazyMap.get(key)，key 是注解的方法名（Override 注解就是"value"）；
  • LazyMap 判断底层 HashMap 不存在这个 key；
  • 执行 factory.transform(key)，把 key 传给 ChainedTransformer；
  • ConstantTransformer 直接丢弃传入的 key，返回Runtime.class作为整条链起点；
  • 后面多个 InvokerTransformer 依次反射：拿到getRuntime方法 → 调用得到 Runtime 实例 → 调用exec执行命令；
  • 执行结果存入底层map 缓存，完成 RCE。

当代理对象调用proxyMap.entrySet()，JDK 把这个方法转发进内层AnnotationInvocationHandler.invoke() invoke里面拿到methodName = "entrySet"，它会直接执行memberValues.get("entrySet")
所以此时传给LazyMap.get的key字符串就是"entrySet"
