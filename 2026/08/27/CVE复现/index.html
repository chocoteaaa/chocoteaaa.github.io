3、启动靶场（重点：必须进入漏洞子目录，读取该目录下 docker‑compose.yml）

示例 1：Log4j2 CVE‑2021‑44228

示例 2：Tomcat CVE‑2025‑24813

  • -d：后台运行容器，不阻塞终端
  • 启动会自动拉取漏洞镜像，创建容器

4、查看运行状态

5、获取 Ubuntu 虚拟机访问 IP（浏览器 / Burp 访问）

拿到 ens33 的 inet 地址，例如 192.168.x.x，这个是 your‑ip，不是容器内部 IPGitHub。

访问格式：http://192.168.x.x:端口，每个漏洞 README 里写好端口。

每个漏洞文件夹里面有README.md，里面写复现 payload、访问端口。

6、实验结束销毁环境❗（一定要在漏洞对应的文件夹执行）

‑v：删除容器 + 数据卷，环境彻底清理干净，不留残留，避免多个靶场互相干扰GitHub。

高频踩坑清单

  1. ❌不要在 vulhub 根目录执行docker compose up，必须进入对应 CVE 子文件夹。
  2. 端口冲突：虚拟机已有程序占用端口，修改docker‑compose.yml的 ports 映射。
  3. 镜像拉取慢：确认 /etc/docker/daemon.json 国内加速器配置正确。
  4. 文档里your‑ip=Ubuntu 虚拟机 IP，不是宿主机 Windows，不是 docker 容器 ipGitHub。
  5. 只做学习复现，不要把漏洞环境暴露到公网。
