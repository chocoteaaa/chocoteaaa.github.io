什么，你想要史上最详细DNSlog外带注入教程？

值得一提的是，注入查询数据库时，即从当前业务库查询其它库的表，属于跨库查询。要跨库读取另一个库的表，账号必须拥有目标库对应的 SELECT 查询权限。而information_schema本身就是系统库，属于典型的跨库查询。

只不过information_schema系统库，普通账号默认就拥有 SELECT 访问权限，不需要额外授权。几乎所有注入环境都可以读 information_schema，这也是脱库的基础，但其中的库并不是 啥都能看见，只能看到你账号本身有访问权限的那些库、那些表。

  • MySQL5.7：不能回收information_schema的 select 权限，强制可以访问；
  • MySQL8.0.12 + 管理员可以执行revoke select on information_schema.*，直接禁止访问该系统库，这种情况注入脱库直接废掉。

UNION 临时表

看了网上的一些文章，在使用联合查询注入的时候，有一个特性，如果你查询的数据不存在，那么联合查询会构造一个虚拟数据，这在查询回显位时经常看到。例如我们-1' union select root,123456 --+，数据库就会出现root和123456这两条数据，页面也有可能回显出来。利用这个特性，插入数据后，对payload进行适当修改，即可用数据库创建的临时数据进行登录。

但是理论上来说查询生成的虚拟行仅存在本次查询内存，不会写入磁盘数据表；反正我自己靶场试了很多次这个方法没成功，之有新发现会更改补充。

报错注入

报错注入不修改数据库数据，仅通过错误使用特殊函数使其报错信息被页面输出。报错信息包含我们要查询的内容，不能使用union联合注入（无回显位）时，可以优先选择报错注入。

前提条件：页面会输出 MySQL 数据库原始报错信息（不打印报错，则无法使用）；参数带入 SQL 内部执行；MySQL 版本、函数存在，部分函数高版本被废弃例如：updatexml /extractvalue：MySQL 5.1 ~ 5.7 可用；MySQL8.0 移除这两个函数，8.0 环境不能用这两套报错注入。

值得注意的是报错函数通常有最长报错输出的限制，面对这种情况，可以用limit、substr等函数进行分割输出，使用group_concat、concat进行结合&隔离，具体视情况而定。

substr(字符串,start,length)
作用：针对已经拿到的那一条字符串，截取其中一部分字符。

  • start：从第几个字符开始切（从 1 计数）
  • length：截取多少个字符

substr不能换表、不能换行，它只处理已经拿到的这一串文本。一般和group_concat搭配

limit offset,count
作用：控制返回哪一张/行记录，用来切换不同的表、不同库、不同数据行。

  • offset：偏移量，从 0 开始，跳过多少行

  • count：最多返回多少行（行数）

  • limit 0,1 → 第 1 张/行 ；limit 1,1 → 第 2 张/行

  • limit 2,3 → 第3、4、5张/行（跳过2张/行，取3张/行）

只负责选整张/行，如果只能输出一行，就用 limit x,1 只吐出一行。一般和 concat 搭配

一、Xpath_expr

updatexml和extractvalue两种，若xpath_expr参数传入非法、不符合 xpath 语法的字符串，MySQL 直接抛出报错，会把你传入的非法字符串原样打印在报错信息中。

若传入系统函数如 database()、concat()则会被执行，从而构造payload实现查询我们需要的数据，再用concat()进行分隔拼接，最终非法 xpath 触发报错，数据就跟着错误输出。

需注意extractvalue、updateXML一次只能返回32字符。

1、 updatexml () 报错注入（最常用）

专门用来修改 XML 文档里面节点的值，函数原型，：

updatexml( xml_doc, xpath_expr, new_val )

参数 1 xml_doc：被操作的 XML 字符串
参数 2 xpath_expr：XPath 路径表达式，必须是合法 xpath 语法，用来定位 xml 里面哪一个节点
参数 3 new_val：要替换成的新内容

参数1、3随便写，参数2用 concat(0x7e,database(),0x7e)，0x7e 为十六进制字符’ ~ ‘ ，将信息分隔便于观察，使用十六进制不需要引号，避免引号冲突，减少被 WAF 识别。

concat()、database() 是系统函数，MySQL 直接执行它，得到当前数据库名字符串，最终字符串：~web~

二、floor()报错注入

别名：group by 重复键报错注入（group by + rand () + count (*)）；可用版本：MySQL5.x、MySQL8.0 都支持

特点：不稳定，随机性，有时候不报错，需要多刷新几次。 前提条件：页面打印 MySQL 原始报错Duplicate entry 'xxx' for key 'group_key'，如果只显示自定义错误页面，无法使用。

核心函数

rand()
无参数随机函数，返回 0 ~ 1 的浮点数，每调用一次，就重新计算一次随机值。
select rand(); – 0.3142
select rand(); – 0.8721

rand(0)
带种子的随机，传入数字种子，随机序列固定，不再随机。floor 报错不能写 rand (0)，必须 rand () 不带种子。
–什么？种子？难道说跟MC里的世界种子一样？也是有种子就有固定世界！

floor(x)
向下取整函数。floor(rand()*2) 结果只会是 0 或者 1。
floor(0.345) → 0
floor(0.999) → 0
floor(1.111) →1

count(*)
聚合函数，统计分组内的行数，会建立一张内存临时分组表。

group by
根据字段分组，把相同值归到同一组。执行时会维护一张内存临时分组表，key 是 group by 的字段，value 是计数。

as
别名 as a：起个名为a， group by a：把这个a分组

payload 核心片段及原理：

有了count(*)，就会生成临时表.

group by按照括号里面拼接出来的字符串做分组，需要一张行数足够多的表作为数据源，驱动循环读取多行，MySQL 会循环读取这张表里每一行，每读一行就执行一次 group by 后面的表达式，如果这张表只有 1 行，rand 只会执行一次，几乎不会触发两次 rand，报错很难复现，所以至少需要有两行数据。

拼接出来的字符串，会作为临时分组表的主键group_key，如 database()+'0' 或 database()+'1'，rand()出的数字随机，若第一次rand出0，则主键为database()+'0'，用该主键key去临时分组表查找，若 key 已经存在：count+1，结束。如果 key 不存在：准备插入这条 key 到临时表。

但准备插入时，MySQL 会第二次重新计算 floor(rand()*2) ，rand 重新运行，可能算出1。 现在要插入的 key 变成：database()+'1'。所以这块还得看点运气，假设database()+'1'这个主键已经存在临时表里。于是发生主键重复冲突。

那么至此就会抛出报错： Duplicate entry 'web' for key 'group_key'，得库名为web。

PS：为什么注入环境里几乎不推荐写 rand (0)？floor(rand(0)*2) 确实可以触发报错，而且是确定性的，经典序列：0,1,1,0,1,1。问题 1：依赖数据源表行数，必须至少 3 行数据，才能走完 0 →1 →1 →0 的序列 问题 2：MySQL8.0 对 group by+rand () 做了优化，rand(0)这套确定性报错在部分 8.0 版本不再复现，但是裸写rand()还有概率触发报错。问题 3：注入子查询嵌套，容易打乱 rand (0) 种子状态

GET_LOCK时间盲注

GET_LOCK()函数:GET_LOCK() 是一个用于实现分布式锁的函数。它通过在数据库中创建一个命名锁，以确保同一时刻只有一个会话能够持有该锁。

利用条件是，开启两个 MySQL 数据库连接，先后在两个连接中使用 GET_LOCK 函数获取相同名字的锁，后面使用 GET_LOCK 函数的连接无法得到锁，等待 timeout秒后执行其它操作。

基础知识

关于域名

域名可以分为5级，从右向左解析，用.分割级别，低级别的域名要在高级别的域名中去解析，所以当security.abc123.dnslog.cn去abc123.dnslog.cn中去解析的时候，就会留下解析记录，通过获取前来解析的低级域名前缀来获取我们需要的信息

每级域名长度只能为63个字符，在mysql中获取到超过63个字节的字符时，会被当作一个错误的域名，不会产生解析，所以abc123.dnslog.cn也不会收到解析的记录，便获取不到想要的信息了

域名里只能出现数字，字母，下划线；在获取到的信息中包含了其他特殊符号如@时，load_file会认为是一个错误的域名，就不会去从网络中解析。

关于DNS、DNS域名解析

DNS(Domain Name System)：就是域名系统，负责把域名转换成IP地址；例如向浏览器访问a.com，浏览器就会将其解析成真实的IP访问对应服务器上的服务。
DNSlog：就是DNS的日志，DNS在域名解析的时候会留下域名和解析IP的记录。

DNS域名解析正常域名解析（以 www.baidu.com，8.8.8.8为例）：你的机器 → 本地缓存 → 本机网卡配置的递归 DNS 服务器（8.8.8.8）发DNS 查询请求，8.8.8.8 去迭代查询根服务器、com 顶级域、baidu 权威服务器，拿到 IP，返回给你的机器。
PS：缓存分层：（浏览器缓存→操作系统缓存→递归 DNS 服务器自身缓存（8.8.8.8））

DNSlog 平台

持有一个域名的权威 DNS 服务器，不做 “域名↔IP 转换”，仅仅记录所有发过来的 DNS 查询请求（查询的子域名、请求时间、来源 IP）。例如abc123.dnslog.cn，当收到递归 DNS 服务器8.8.8.8发过来的 DNS 查询包，把要查询的子域名以及来源 ip：8.8.8.8记入日志。

PS：中途过程：Windows 本机 DNS 客户端向本机配置的8.8.8.8发送 DNS 查询，请求解析域名abc123.dnslog.cn。递归服务器检查自身缓存再迭代查询，递归查到 .cn 服务器返回：dnslog.cn 的权威 DNS 就是 DNSlog 平台的服务器，于是8.8.8.8发起全新的 DNS 查询，发给 DNSlog 平台（权威 DNS）查询域名：abc123.dnslog.cn

PS：靶机系统配置的递归 DNS 不一定是 8.8.8.8：家庭 / 办公内网：路由器运营商 DNS一大堆不同 IP；企业内网：企业自建内网 DNS 服务器；靶场虚拟机：使用宿主机网关提供的 DNS；云服务器：云厂商内部 DNS 服务器。所以 DNSlog 日志里来源 IP 五花八门，绝大多数情况都不是 8.8.8.8，但全部都是「递归 DNS 服务器」的 IP。

关于SMB

Server Message Block，服务器消息块，Windows 网上邻居、共享文件夹背后的协议，端口：现代 SMB TCP 445；老版本 NetBIOS SMB 使用 139 端口。

说白了就是能让 Windows 访问另一台电脑的共享文件夹，你要访问别人服务器那肯定要一个ip或者域名呗。

关于UNC路径

Windows 用来访问局域网 SMB 网络共享文件夹的路径格式，标准 UNC 格式：\\目标域名或服务器名\共享文件夹名\共享内的文件，双反斜杠：标记这是网络共享路径，不是本地磁盘，示例（Windows 资源管理器访问局域网共享）：\\192.168.1.100\share\test.txt

windows 若遇到\\abc123.dnslog.cn\V\abc这种用域名而非 IP 的 UNC 路径，第一件事：做 DNS 域名解析，把域名解析成 IP，之后才会尝试 SMB 连接访问共享资源。 该注入就是滥用这个 DNS 解析行为，哪怕这个域名、共享文件夹根本不存在，DNS 解析依然会执行，根本不需要 SMB 连接成功，只要触发 DNS 查询就把数据带出来。

MySQL 字符串里面的转义：在 MySQL 字符串中，\是转义字符，UNC 需要开头2 个真实反斜杠，所以 SQL 字符串里面必须写 \\\\（4 个反斜杠）（我感觉这个好像……）

前提条件

  1. 首先要有注入点
  2. MySQL 是 Windows 系统，Linux 没有 UNC 路径，load_file("\\\\xxx")不会触发 DNS 解析。
  3. 当前 MySQL 账号拥有 FILE 权限 (file_priv=Y)
  4. @@secure_file_priv != NULL，不能是 NULL，否则 load_file 直接失效。
  5. 运行 MySQL 的 Windows 服务器可向外发送 UDP53 DNS 数据包，注意这里非’’得有请求url权限”，SSRF才是
  6. WAF 没有过滤load_file、concat。

DNSlog外带原理：DNS在解析的时候会留下日志，我们将信息放在高级域名中，传递到自己这里，然后通过读日志获取信息。

注入核心原理：

1、MySQL 的load_file()拿到路径字符串后，调用 Windows 系统 API，把这个字符串原样传给操作系统，请求打开这个路径对应的文件；
2、Windows 操作系统检测路径开头是\\，判定为 UNC 网络共享路径，对 UNC 里面的主机域名发起 DNS 解析。
3、Windows 本机 DNS 客户端，向本机配置的递归 DNS 服务器（例如 8.8.8.8）发送 DNS 查询，请求解析 UNC 路径里的主机名。
4、递归服务器迭代查询，最终将查询请求转发给 DNSlog 平台（该域名的权威 DNS 服务器）。
5、DNSlog 平台收到 DNS 查询报文，提取报文中的子域名（也就是窃取到的数据）存入日志，返回一段虚假 IP。
6、至此已结束，之后尝试 SMB 连接；SMB 访问失败，返回失败；MySQL 收到失败结果，load_file()最终返回 NULL。

POST注入

基础概念

GET 注入：参数放在 URL ?id=xxx，通过 Query 字符串传递。
POST 注入：参数放在 HTTP 请求体（body）里面，不在 URL 地址栏显示，常见表单：登录框、查询框，提交账号密码，数据包 body 携带参数。

底层 SQL 逻辑、payload 函数、注入类型（联合 / 报错 / 布尔 / 时间 / DNSlog）和 GET 注入完全一模一样；只是参数传递位置变了。

1.get提交可被缓存，post不会
2.get提交参数会保留在浏览器历史记录，post不会
3.get可被收藏为书签，post不会
4.get提交最长2048字符；post无长度要求，除允许用ascii字符，还可二进制数据

HTTP 请求头注入

产生原因：后端会查询或记录HTTP请求头内容，操作时直接读取 HTTP 请求头里的数据，并且未做安全检查、过滤，直接拼接到 SQL 语句执行，就会产生 HTTP 请求头 SQL 注入。常见注入请求头：User-Agent、Referer、X-Forwarded-For(XFF)、Cookie（Cookie 也算请求头）

关于http请求头详细学习可见我bro文章：详解请求头信息 | Yxing
关于用哪种注入方式主要是看源代码的设置，若后端源码如下即可union注入：

$sql = “SELECT * FROM users WHERE username=$session_id LIMIT 0,1”;

若源码如下则可报错注入、时间盲注、DNSlog外带注入：

$sql = “insert into log(user_agent) values (‘$ua’)”;

一般都是报错注入，union比较少，可用BP等工具抓包改payload，也可以用Hackbar这样的插件。需要注意的是语句结尾需要括回来，注入的时候记得加上。

uagent（用户代理，UA），特殊的字符串头，使服务器能识别客户操作系统及版本、CPU类型、浏览器及版本、浏览器渲染引擎、浏览器语言、浏览器插件等，内容就是浏览器及版本信息、电脑信息等。常用于限制打开软件，浏览器，及上网行为管理

Cookie：

Cookie 就是一段字符串，是浏览器保存服务器返回数据的方法，通常保存用户身份信息。是某些网站为了辨别用户身份，进行Session跟踪而储存在用户本地终端上的数据（通常经过加密），由用户客户端计算机暂时或永久保存的信息，session当访问服务器某个网页的时候，会在服务器端的内存里开辟一块内存，这块内存就叫做session，而这个内存是跟浏览器关联在一起的。这个浏览器指的是浏览器窗口，或者是浏览器的子窗口，意思就是，只允许当前这个session对应的浏览器访问，就算是在同一个机器上新启的浏览器也是无法访问的。而另外一个浏览器也需要记录session的话，就会再启一个属于自己的session。也称为会话控制。

cookie：临时身份证（部分xss核心）:
setcookie(name,value,expire,path,domain,secure)
name:必需。名称
value:必需。值
expire:必需。有效期
path:可选。服务器路径
domain:可选。域名
secure:可选。是否通过安全的HTTPS连接来传输cookie
