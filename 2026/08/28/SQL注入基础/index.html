发表于2026-08-28|更新于2026-08-30
|总字数:4453|阅读时长:19 分钟|浏览量:

​

很久之前学的，现在来总结一下，有点一些细节忘记了，有错误不足之处望指出。👀

​ 大多数的web应用都需要与数据库进行交互，在web表单，cookie及输入参数等收到的值传递给 sql 查询之前（该查询在数据库服务器上执行），web应用开发人员没有对其进行验证或者过滤不充分，那么通常会出现sql注入漏洞。

​ SQL注入漏洞一般是拿来获取数据库信息的，如果攻击者能够修改sql语句，那么该语句将与应用的用户具有相同的权限。当使用sql服务器执行与操作系统交互命令时，该进程将与执行命令的组件（如数据库服务器、应用服务器或web服务器）拥有相同的权限，这种权限的级别通常很高。如果攻击者执行以上恶意代码的插入操作成功，那么用户数据库服务器或者整个应用会遭到破坏，甚至被控制。

​ 简单来说就是开发者没有对用户的输入做出严格的限制，导致用户可以通过恶意的输入拼接正常的sql语句最后执行命令。

一些权限问题：

查询权限和文件权限两个东西分清楚，CTF中一般不涉及操作系统权限，优先级从低到高写。

操作系统 (Linux/Windows) 权限：

运行mysqld 数据库进程的那个系统用户。就是操作系统上跑 MySQL 服务的用户，不是网站 web 用户，也不是数据库账号。

系统用户想要写文件到 /var/www/html（网站根目录），则操作系统上必须对这个文件夹拥有 w 写权限。 如果用户没有写权限，哪怕file_priv=Y、secure_file_priv=""，函数into outfile依旧写不进去，不会报错但文件不会生成。

读文件同理：load_file("/etc/passwd")，操作系统 mysql 用户要有 r 读权限。

FILE权限：

file_priv 存在于 mysql.user 表，属于账号（用户）的权限标记。 针对某个 mysql 账号，标记这个账号有没有资格调用文件类函数（load_file、into outfile）。优先级高于操作系统权限。

  • Y ：账号具备文件操作资格
  • N ：账号直接没有资格，直接禁止调用文件函数

文件读写权限（@@secure_file_priv;）：

@@secure_file_priv 是MySQL 服务全局变量，整个 MySQL 实例一套配置，不属于某一个库，也不属于某一个用户。 用来限制文件读写的目录范围，是 MySQL 的安全配置，优先级高于 file_priv。

返回值 效果
NULL 完全禁止文件读写，MySQL5.7 + 默认，就算有 FILE 权限也不能读写文件
""（空字符串） 无限制，可以读写任意路径文件
/tmp/ 仅允许读写这个指定目录下的文件

这里需要注意网页可能区分不开（NULL）和（””）两个值；具体判断需：

  • 回显 1 → @@secure_file_priv 是 NULL，禁止 load_file()、into outfile，文件读写全部废掉，不用再试读文件写 shell。

  • 回显 0 → @@secure_file_priv 是空字符串 ""

    mysql 层面放开路径限制，可以读写任意路径，但还需要另外两个条件：

    1. mysql 账号拥有 FILE 权限
    2. mysql 操作系统用户拥有对应文件读写权限

  • 如果回显 /tmp、/var/lib/mysql-files 这类路径字符串：代表仅允许这个目录，其他目录 load_file 返回 null。

information_schema

​ MySQL 5.0 及以上版本内置系统库 information_schema，是保存数据库元数据（库名、表名、列名、权限、字符集等）的虚拟库，没有实际磁盘文件，数据实时计算生成。SQL 注入中，就是查询这个库来爆破库、表、列。MySQL8.0 中基本保留这些表，部分权限机制变化；MariaDB 基本兼容。

核心常用表（注入最常用）

1、SCHEMATA 库信息表，存储所有数据库名，重要字段：

  • SCHEMA_NAME：数据库名称

注：SCHEMATA 库信息表是我经常忽略的一张表：:joy_cat:

2、TABLES 表信息表，存储所有数据库的表名，字段：

  • TABLE_SCHEMA：所属数据库名
  • TABLE_NAME：表名
  • TABLE_TYPE：表类型 (BASE TABLE 普通表，VIEW 视图)
  • ENGINE：表的存储引擎（如 InnoDB、MyISAM）。
  • TABLE_ROWS：表中的行数（近似值）。
  • CREATE_TIME：表的创建时间。

3、COLUMNS 列信息表，存储所有表的列名字段，注入最重要的一张表，字段：

  • TABLE_SCHEMA：库名
  • TABLE_NAME：表名
  • COLUMN_NAME：列名
  • DATA_TYPE：字段数据类型
  • IS_NULLABLE：列是否允许 NULL 值。
  • COLUMN_DEFAULT：列的默认值。
  • CHARACTER_MAXIMUM_LENGTH：字符类型列的最大长度。

补充：sys 库（MySQL5.7 新增）是视图封装，底层依然查询information_schema、performance_schema，注入一般不优先使用。对比performance_schema性能监控库，用于性能统计，一般不用来注入脱库。文章末尾加上了其它表。

脱库（Dump Database）：通过漏洞把数据库里面的数据全部盗取导出出来

2、判断是否存在注入点：

用单引号判断，即在参数后面加上单引号（无论字符型/数字型都会因单引号错）

  • 字符型注入：单引号不匹配大概率报 SQL 语法错误；
  • 整型（数字型）注入：正常业务 SQL 不带引号，多写 / 少写单引号，会直接产生语法报错。

1、MySQL 数据库报错：You have an error in your SQL syntax。高概率存在注入，单引号破坏了原 SQL 引号语法。

2、页面空白、内容异常、跳转：有可能注入；

3、页面完全无变化：大概率不存在数字型注入，继续往下测试。

PS：information_schema在其他注入中会遇到的表

  1. VIEWS 视图信息：存储所有视图定义
  • TABLE_SCHEMA、TABLE_NAME：视图所属库、视图名
  • VIEW_DEFINITION：视图原始 SQL 语句，注入可以读视图源码
  1. USER_PRIVILEGES 用户全局权限：展示 mysql 账号全局权限，不需要访问 mysql.user 表也可以拿到部分权限信息
  • GRANTEE：账号，如'root'@'localhost'
  • PRIVILEGE_TYPE：权限名称 SELECT,FILE 等

  1. SCHEMA_PRIVILEGES 库级权限：某个账号对某个数据库拥有的权限。

  2. TABLE_PRIVILEGES 表级权限：账号对单张表的权限。

  3. COLUMN_PRIVILEGES 列级权限：账号针对某一列的权限。

  4. KEY_COLUMN_USAGE：存储主键、外键约束信息，有时候当 columns 表无法读取时，可尝试拿列名。

  5. PROCESSLIST：information_schema.processlist 查看当前数据库正在执行的 SQL 线程，需要 PROCESS 权限。(mysql5.7 以后推荐 sys.processlist)

  6. FILES：存放 innodb 文件元信息，不能用来读文件，不要和 load_file 搞混。

  7. ENGINES：存储数据库支持的存储引擎 InnoDB/MyISAM 等。

  8. GLOBAL_VARIABLES / SESSION_VARIABLES：全局变量、会话变量。 @@version等价于查询这里，可以拿到版本号、secure_file_priv（文件读写关键参数）。
