JavaScript 极简基础语法

前面我们学习的 Java 是强类型、编译型语言，而 JavaScript 是运行在浏览器、Node.js 环境中的弱类型、动态类型解释型脚本语言。

二者语法有相似之处，但核心类型系统完全不同：Java 变量类型固定不变，JS 变量类型可动态随意变更，无需提前声明类型。

JS 核心特点

  • 弱类型：无需手动定义变量类型，赋值什么数据，变量就是什么类型
  • 动态类型：程序运行过程中，变量类型可随时修改切换
  • 解释执行：无需编译，浏览器/Node 逐行解析运行代码
  • 大小写敏感：name 和 Name 是两个完全不同的变量

变量声明 var / let / const

JS 提供三种变量声明方式，其中 let、const 是 ES6 新标准，优先使用；var 为旧语法，项目中彻底废弃。

var（不推荐）

函数级作用域，无块级作用域限制，存在变量泄露、可重复声明等诸多 bug，现代 JS 开发完全不用。

let（可变变量）

块级作用域，支持后续修改变量值，不允许重复声明同名变量，适用于值会变动的场景。

const（常量，优先使用）

块级作用域，声明时必须初始化赋值，默认禁止重新绑定新值。

核心注意点：const 仅锁定变量的引用绑定，若绑定的是引用类型（对象、数组），内部属性、元素可以正常修改。

开发黄金口诀：能 const 就 const，不能修改再用 let，坚决不用 var

JS 数据类型

JS 数据类型分为 7种基本类型（值类型） 和 1种引用类型（对象类型）。

七大基本类型

  • number：数字类型，不区分整数、小数、浮点数，统一归为 number
  • string：字符串类型，支持单引号、双引号、反引号定义
  • boolean：布尔类型，仅包含 true、false 两个值
  • null：空值，程序员手动赋值的空对象标识
  • undefined：未定义，变量声明未赋值时，系统默认值
  • symbol：ES6 新增，生成唯一不重复标识，用于解决属性冲突
  • bigint：ES2020 新增，超大精度整数，弥补 number 精度丢失问题

引用类型

核心为 object，数组、函数、普通对象、日期对象等，都属于 object 引用类型。引用类型变量存储的是内存地址，而非真实数据。

类型判断 typeof

typeof 是 JS 内置的类型判断关键字，可快速识别数据类型，存在一个经典历史 bug。

重点：typeof null === ‘object’ 是 JS 早期设计缺陷，不代表 null 属于对象类型。

字符串 String

JS 字符串支持单引号、双引号、反引号三种定义方式，反引号模板字符串为开发首选，支持换行、变量嵌入。同时字符串为不可变数据，所有操作均返回新字符串，不修改原字符串。

JS 与 Java 核心区别总结

  • Java：强类型、编译运行、变量类型固定、仅有 == 判断
  • JS：弱类型、解释运行、变量类型动态可变、区分 == 宽松相等 / === 严格相等
  • Java 集合固定类型长度；JS 数组动态可变、可存储任意类型
  • Java 面向对象繁琐；JS 对象、类、继承语法极简灵活
  • JS 函数为一等公民，支持箭头函数、解构、展开等现代语法

小结

  1. 变量规范：优先 const，其次 let，彻底废弃 var；
  2. 数据类型：7种基本类型 + 1种引用类型，typeof null 为历史bug；
  3. 核心规范：所有相等判断**只用 ===、!==**，杜绝隐式类型转换；
  4. 高频重点：数组高阶方法、ES6解构/展开、箭头函数、类继承是开发核心；
  5. 字符串、数组均为浅操作，字符串不可变、展开运算符仅浅拷贝。

JavaScript 数组高阶方法

前面我们学完了 JS 基础语法，知道数组是 JS 存放批量数据的核心结构。

在 Java 中，遍历、处理数组数据大多依赖普通 for 循环；但在 JS 开发中，几乎不用原生 for 循环做数据处理，全部使用数组高阶方法（forEach /map/filter /reduce）。

高阶方法是 JS 函数式编程的核心，也是工作中处理后台列表、页面渲染、数据筛选、数据统计的必备语法。

本文讲解四个必掌握、高频、面试必考的数组高阶方法： forEach、map、filter、reduce

  2. 遍历过程中自动拿到：当前元素、下标、原数组

  3. 初始值必须写，是开发规范

四方法核心对比

  1. forEach：只遍历、不返回、纯执行（消费数据）
  2. map：遍历加工、一一对应、返回等长新数组（加工数据）
  3. filter：遍历判断、条件筛选、返回过滤新数组（挑选数据）
  4. reduce：遍历累计、汇总计算、返回单个结果（统计数据）

易错点总结

  1. forEach 没有返回值，不能用来接收数据结果
  2. map 必须 return，否则得到全 undefined 数组
  3. filter 是条件为 true 保留元素，不要写反逻辑
  4. reduce 必须设置初始值，否则空数组报错、数值异常
  5. 四个方法全部不会修改原数组，都是返回新数据

小结

  1. 只遍历、不处理数据 → forEach
  2. 批量加工、格式化数据 → map
  3. 筛选、过滤数据 → filter
  4. 求和、统计、汇总、复杂计算 → reduce

DOM 文档对象模型

前面我们学完了 JS 数组高阶方法，这些都是 JavaScript 本身的语法。而 DOM 是浏览器提供的 API，让 JS 可以操作 HTML 页面上的标签元素。

简单理解：浏览器把整个 HTML 文档转换成一棵节点树，JS 通过 DOM 拿到这棵树上的节点，从而实现修改页面文字、颜色、添加删除标签、绑定点击事件等网页交互效果。

注意：DOM 不属于 ECMAScript 语法，是浏览器环境独有的；Node.js 里默认没有 DOM。

DOM 核心概念

DOM（Document Object Model）文档对象模型。

  • document：整个页面文档的根对象，所有 DOM 查找都从它开始
  • 节点：HTML 里每一个标签、文字、注释都是节点，最常用的是元素节点（标签）
  • 核心流程：获取页面元素 → 修改元素内容 / 属性 → 监听用户事件

DOM 易错点总结

  1. JS 代码写在 head 里时，执行的时候 HTML 还没渲染，获取元素会得到 null；解决办法：script 标签放在 body 末尾，或者用 DOMContentLoaded 等待页面加载完成
  1. querySelectorAll 返回 NodeList，不是数组，直接调用 map 会报错，需要 Array.from 转换
  2. innerHTML 会解析 HTML，存在 XSS 风险，纯文本优先 innerText /textContent
  3. classList 操作 class 不会覆盖原有 class，比直接赋值 className 更安全
  4. 动态生成的元素，直接 addEventListener 绑定会失效，优先用事件委托绑定在父容器

小结

  1. DOM 是浏览器提供操作 HTML 节点的 API，核心入口是 document；
  2. 查找元素首选 querySelector/querySelectorAll；
  3. 修改内容区分 innerText 和 innerHTML，修改样式优先控制 class；
  4. 新增节点使用 createElement + append；
  5. 事件是页面交互核心，事件委托适合动态列表，利用事件冒泡实现；
  6. 结合前面学的数组高阶方法，可以从页面拿到一组元素，转数组后用 map/filter 批量处理。

BOM 浏览器对象模型

前面我们学完了 DOM，DOM 用来操作 HTML 页面里的元素；而 BOM（Browser Object Model）浏览器对象模型，是浏览器提供的一套 API，用来操作浏览器窗口本身。

简单理解：DOM 管页面内容，BOM 管浏览器窗口，BOM 的核心入口是 window 对象。

注意：BOM 没有统一标准，由浏览器厂商实现；window 是全局对象，我们之前写的全局变量、全局函数都挂载在 window 上，平时写代码可以省略 window。

window 全局对象

window 是 BOM 的根对象，代表浏览器窗口。

  • 所有 BOM 的子对象都是 window 的属性：document、location、history、navigator、screen
  • 全局声明的变量、函数，都会成为 window 的属性和方法

区分：document 既是 window 的属性，又是 DOM 的入口对象，所以 DOM 属于挂载在 window 上的一部分。

弹窗方法（了解，开发很少用）

window 提供三种原生弹窗，会阻塞代码执行，不适合正式项目，一般只用于调试。

三、定时器（BOM 重点）

定时器用来延迟执行代码或者周期性重复执行代码，属于 window 的方法。

setTimeout 延时定时器

等待指定毫秒后执行一次回调函数，返回定时器编号，用于取消。

setInterval 周期定时器

每隔指定毫秒重复执行回调函数，需要手动停止，否则会一直循环。

重要注意点：

  1. 时间单位是毫秒，1 秒 = 1000 毫秒
  2. JS 是单线程，定时器只是把回调放进任务队列，不一定能精准按时执行
  3. 定时器编号是数字，可以直接传给 clearTimeout/clearInterval 取消

location 地址对象

（控制页面地址、跳转、刷新）window.location 用来读取、修改浏览器地址栏信息。

猫咪案例场景：添加猫咪成功后，跳转猫咪列表页

history 历史对象

（控制浏览器前进后退）window.history 操作浏览器访问历史记录，不会触发页面刷新。

注意：history 只能操作当前会话的历史，不能读取别人的访问地址，有安全限制；前端路由（Vue/React Router）底层基于 history API。

BOM 易错点总结

  1. window 可以省略，setTimeout() 和 window.setTimeout() 等价
  2. setTimeout 只执行一次，setInterval 循环执行，记得保存编号用于清除，防止内存泄漏
  3. location.href 跳转会生成历史记录，replace 不会
  4. localStorage 只能存字符串，对象、数组必须配合 JSON.stringify/ JSON.parse
  5. scroll 事件绑定在 window 上，而点击等元素事件绑定在 DOM 元素上
  6. BOM 是操作浏览器窗口；DOM 是操作页面标签元素，document 是两者交汇点

小结

  1. BOM 核心是 window 全局对象，用来操作浏览器窗口，和页面标签无关；
  2. 定时器 setTimeout、setInterval 是 BOM 最常用功能，注意及时清除；
  3. location 控制页面跳转刷新，history 控制前进后退，navigator 读取浏览器设备信息；
  4. localStorage、sessionStorage 实现前端本地数据持久化存储；
  5. BOM 和 DOM 经常配合使用：DOM 拿到页面按钮，绑定 click 事件后，调用 BOM 的定时器、跳转、存储能力完成交互。
