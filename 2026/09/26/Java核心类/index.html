意义

主要有两大用途：
1、传递数据：把一组相关的数据打包成一个对象，便于在方法间、模块间传输（比如从数据库读出一只猫的信息，封装成 Cat 对象传给业务层）；|
2、被工具识别：因为命名规范统一，IDE 和框架可以自动分析 JavaBean 有哪些属性，进而自动生成代码——最典型的场景就是图形界面的可视化设计器：拖一个控件到窗体上，属性面板自动列出所有可配置项，背后靠的就是反射读取 getter/setter。

字符编码

早期计算机只需要处理英文、数字和基础符号。美国国家标准学会制定了 ASCII 编码，只用 1 个字节存储字符，编码范围是 0~127，字节最高位固定是 0。 例如字符'A'的 ASCII 编码是0x41，字符'1'的编码是0x31。

但 ASCII 只能表示英文字符，想要存放汉字，1 个字节就不够用了。 我国制定了 GB2312 编码，使用 2 个字节来表示一个汉字，并且汉字编码的第一个字节最高位为 1，以此和 ASCII 字符区分。例如汉字'中'的 GB2312 编码是0xd6d0。

类似地，日文有 Shift_JIS、韩文有 EUC-KR。这类各个国家单独制定的编码标准互不兼容，在混合多种文字时很容易出现乱码。

为了解决多语言冲突问题，统一码联盟推出了 Unicode。Unicode 把全世界主流语言的字符都收纳到一套编码体系里，中文、日文、韩文等字符可以共存，不会发生编码冲突。 Unicode 字符占用 2 字节或更多字节，我们对比几个字符的编码：

英文字符'A'：

英文字母的 Unicode 编码，就是在 ASCII 编码前面补一个值为 0 的字节。

汉字'中'：

很多人容易混淆：Unicode 是字符集，UTF-8 是 Unicode 的一种存储 / 传输实现方式。 如果直接用原始 Unicode 保存大量英文文本，英文字符的高字节永远是 0，会白白浪费存储空间。 于是 UTF-8 诞生，它是变长编码：把 Unicode 字符编码成 1~4 个字节。

  • 英文字符'A'的 UTF-8 编码就是0x41，和 ASCII 完全兼容；
  • 汉字'中'的 UTF-8 编码占 3 字节：0xe4 0xb8 0xad。

UTF-8 还有一个优势：容错性强。数据传输时如果某一段字节损坏，只会破坏当前这一个字符，不会连累后面所有字符。因此网络传输普遍选用 UTF-8。

包装类型

意义：包装类型把 Java 基本数据类型封装成对象，让基本类型可以用于泛型、集合等只能接收引用类型的场景，并提供各类工具方法。
（就是给基础数字、布尔值套个对象外壳，方便放进集合、泛型里用）

前情

Java 的数据类型分为基本类型和引用类型

基本类型一共有 8 种，分别是 boolean、byte、short、int、long、float、double、char，基本类型变量直接存储数值本身

引用类型变量存储的是对象在堆中的地址，并不存放对象本身，像 String、自定义的 Cat 类、数组、接口以及各个包装类都属于引用类型，二者还支持自动装箱和自动拆箱，用来在基本类型和对应的包装类之间自动转换。

即：
基本类型：byte，short，int，long，boolean，float，double，char；
引用类型：所有class和interface类型。

最佳方案

  1. 优先按照语义写代码，不要依赖底层缓存这种内部实现做判断。
  2. 创建包装对象时，优先使用静态工厂方法valueOf()，而不是new。

Integer.valueOf()就是典型的静态工厂方法，它会尽可能复用缓存里的对象，减少内存占用。调用方不用关心底层是新建对象还是复用缓存，只需要拿到包装实例即可。

  • 转 byte：byteValue()
  • 转 short：shortValue()

enum 的比较

enum 属于引用类型。普通引用类型推荐用equals()，但枚举是特例：每个枚举常量在 JVM 中只有唯一实例，所以可以直接用==比较。

enum 类型本质

enum 本质就是 class，只是有几条特殊规则：

1、自动继承java.lang.Enum，不能再继承其他类，也不能被别的类继承；
2、不能用new手动创建枚举实例，实例全部由 JVM 预先创建；
3、每个枚举常量都是全局唯一的实例；
4、可以直接在 switch 中使用。
