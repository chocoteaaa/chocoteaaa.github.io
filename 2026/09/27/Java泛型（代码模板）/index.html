泛型是一种“代码模板”，可以用一套代码套用各种类型。泛型就是给类或者方法留一个 “类型空位”，用的时候再指定是什么类型。有了它，同一个容器既能存字符串又能存数字，不用写多套重复代码；编译器还能提前帮你检查放进去的数据对不对，避免后面强制转型时报错，只是编译之后这个类型信息会被擦掉。

向上转型

在泛型代码中，向上转型依然遵循多态思想，但只针对容器本身，不针对容器内部的元素类型。当两个泛型容器的内部类型参数完全一致时，实现类可以向上转型为接口类型，例如 ArrayList 可以转为 List

泛型向上转型（T 保持一致）的意义：在保证泛型类型约束不变的前提下，面向接口编程，剥离具体实现类，提升代码灵活性，方便替换底层容器。

在 Java 标准库中，ArrayList实现了List接口（尖括号外层的类与接口存在实现 / 继承关系），并且同一个类型参数 T 的前提下，它可以向上转型为List：

也就是说：ArrayList 可以向上转型为 List，前提是尖括号内的类型参数T保持一致。

重点：**不能把ArrayList向上转型为ArrayList，也不能转型成List**。

我们来推演一下，如果 Java 允许这么转型，会发生什么问题：

原因拆解： numberList 和 integerList 引用的是同一个底层对象，这个对象的真实类型是ArrayList，它本来只允许放Integer。 一旦允许转型成ArrayList，编译器就会放行Float这类 Number 的子类，往里面写入非 Integer 的数据。等到取出数据的时候，就会触发类型转换异常。

为了杜绝这种隐患，Java 编译器直接禁止这种转型。

特别注意 ArrayList 和 ArrayList 完全不存在继承关系。 虽然Integer是Number的子类，但是泛型容器ArrayList并不是ArrayList的子类。

泛型继承关系示意

只有类型参数 T 相同的时候，才存在向上转型（类→接口）；类型参数 T 不一样，哪怕 T 之间有父子关系，泛型容器之间没有继承关系，不能向上转型

所以，泛型容器向上转型，需要同时满足两点：尖括号外层的类与接口存在实现 / 继承关系，并且尖括号内的类型参数 T 完全一致。内部 T 就算有父子继承关系，也不代表对应的泛型容器之间存在继承关系。

擦拭法（Type Erasure）

泛型是一种类似 “模板代码” 的技术，不同编程语言实现泛型的方案并不一样。

Java 的泛型采用擦拭法（Type Erasure）实现。：泛型只在源码和编译阶段生效，由编译器负责做类型检查、自动插入类型转换；代码编译成字节码之后，尖括号中的泛型信息会被清除，JVM 运行时看不到泛型。

简单来说：Java 虚拟机并不认识泛型，泛型的类型校验全部由编译器在编译阶段完成，编译之后泛型信息会被擦掉。

局限

泛型参数不能是基本类型-1

<T>不能填int、boolean、double这类基本类型。因为擦除后会变成Object，而Object只能存放对象，存不了基本值，无法直接承载基本类型。

只能是引用类型：类、接口、数组、包装类。

引用类型就是对象类型，变量存的不是值本身，而是对象在堆里的地址。Java 里一共 4 大类：
1、类（Class）：自己写的类、JDK 自带类 例：String、Cat、ArrayList、Integer
2、接口（Interface） 例：Comparable、List、Runnable
3、数组（不管数组里面是基本类型还是引用类型，数组本身都是引用类型） 例：int[]、String[]、Cat[]
4、枚举、记录类（enum /record） 例：自己定义的枚举CatBreed、record CatInfo(...)

一句话区分：new 出来的、或者可以当成对象的，基本都是引用类型；8 个基础关键字是基本类型。

基本类型只有 8 个：byte short int long float double boolean char，不能直接放进泛型尖括号。如果需要，只能使用对应的包装类型Pair<Integer>。

  • int → Integer
  • boolean → Boolean
  • char → Character
  • double → Double

补充：自动装箱会帮你把1自动变成Integer.valueOf(1)，写起来看着像直接放数字。

无法区分带泛型的 Class 对象-2

特点：final，不能重写；作用：返回这个对象运行时对应的Class对象。

<? extends T> 可读、不可写（null 除外） 生产者，往外拿数据
<? super T> 可写、读取只能拿到 Object 消费者，往里存数据

小猫对照 Pair<? extends Cat>：可取出小猫，但不能随便往里塞新猫（不知道容器限定的是暹罗还是布偶）
Pair<? super Cat>：可以往里面放入猫咪，但是取出来不能确定精确品种

PECS 原则

Producer Extends，Consumer Super

  • Producer（生产者，向外提供数据，需要读取）：用 extends
  • Consumer（消费者，接收存入数据，需要写入）：用 super

以 Collections.copy 源码思路举例：

  • src 来源列表，只负责读出，标记 List<? extends T>
  • dest 目标列表，只负责写入，标记 List<? super T>

这个方法的类型限制带来天然的方向约束：

无限定通配符 Pair<?>

还有一种没有上界、也没有下界的通配符，直接写 ?，叫无限定通配符。

规则：

  • 不能调用 set 方法存入任意对象（null 除外）
  • get 拿到的只能用 Object 接收，不能拿到具体 T 类型

也就是说：几乎不能读写内部元素，仅适合不关心元素具体类型、只做判断的场景。

示例：判断 Pair 里两个元素是否存在 null

很多时候，我们可以直接用泛型参数 <T> 替代 ?，可读性更好：

<?> 有一个很特殊的性质：**Pair<?> 是所有 Pair<T> 的共同超类型**。 任何 Pair<Cat>、Pair<Siamese>、Pair<Integer> 都可以安全向上转型为 Pair<?>。

小结

1、? super T 下界通配符：接收 T 以及 T 的父类的泛型容器，适合写入，不适合读取精确类型；
2、PECS：生产者 extends，消费者 super，是选择两种通配符的核心判断依据；
3、无限定通配符 ?，是所有Pair<T>的父类型，读写限制极强，一般只用在不关心元素类型的简单判断场景。
