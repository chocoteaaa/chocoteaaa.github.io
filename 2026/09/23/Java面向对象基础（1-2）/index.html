历史

Java 由被称为 “Java 之父” 的詹姆斯・高斯林（James Gosling）在上世纪 90 年代初开发，最初隶属于 SUN 公司（后 SUN 被 Oracle 收购）。这门语言最早命名为 Oak，设计目标是用于小型家电的嵌入式开发，但当时市场反响不佳。随着互联网兴起，SUN 改造了 Oak，由于 Oak 商标已被注册，在 1995 年正式以 Java 名称对外发布，随后凭借互联网浪潮迅速成为主流网络编程语言。

Java 兼具编译型与解释型语言的特点。C/C++ 这类纯编译语言会直接编译成对应平台 CPU 的机器码，跨平台需要单独编译多个版本；Python 这类解释型语言可直接执行源码，但运行性能较差。Java 的解决方案是：源码先编译成字节码，再由不同平台的 JVM（Java 虚拟机）加载执行字节码，实现一次编写，到处运行。

为保障各平台虚拟机都能正确执行字节码，SUN 制定了 JVM 规范，JVM 拥有良好的向下兼容性，低版本 Java 编译出来的字节码，能够在高版本 JVM 上正常运行。

面向对象基础

概念

Java是一种面向对象的编程语言。面向对象编程，英文是Object-Oriented Programming，简称OOP。和面向对象编程不同的，是面向过程编程。面向过程编程，是把模型分解成一步一步的过程。面向对象编程，是一种通过对象的方式，把现实世界映射到计算机模型的一种编程方法。

例如，在现实中，“人”是一个抽象的概念，而具体到小明小红，就是一个个具体的概念，所以针对“人”，我们可以定义为一个（class），而具体的人则是实例（instance）。

  • 人：class Person {}
  • 实例：Person navy = new Person()

注意，什么是类型，什么是实例（对象），什么是变量（引用类型 变量 = new 实例类型）：

  • 前Person：变量navy的声明类型（引用类型、编译类型），编译器看这个类型做检查
  • navy：栈上的引用变量，存的是这个对象的内存地址，用来指向这个实例
  • 后Person：实例的实际类型（运行类型、真实类型）
  • 整体 new Person()：在堆内存创建对象（实例）

覆写Object

因为所有的class最终都继承自Object，而Object定义了几个重要的方法：
1、toString()：默认类名@哈希值，覆写用来给对象友好文字描述，System.out.println(对象)会自动调用；可以体现多态。
2、equals()：默认==比较内存地址，业务上一般覆写，按属性判断内容是否相等。
3、hashCode()：返回哈希整数，约定：equals返回true，hashCode必须相同，用于 HashMap 等集合。
4、getClass()：final修饰，不能覆写，拿到运行时真实类型，和多态搭配看实际对象类型。
5、clone()、finalize()现在基本不推荐使用

那覆写Object的意义在哪？个人认为有两个（覆写 = 换语义；协议 = 自动被调用）：
1、把 Object 原生基于内存地址 / 对象身份的默认语义，替换成符合业务的对象内容语义：让对象支持友好打印、按属性做相等判断、在 HashMap/HashSet 这类哈希容器里正常工作。
2、自定义普通方法只能在你主动调用的地方生效；但覆写 toString() / equals() / hashCode() 等于接入 Java 内置的通用协议。JDK、各种框架的已有代码会自动调用这些方法，不需要别人看你的源码，就能获得预期行为。

抽象类

原理

在上面我们知道，包含抽象方法时，普通类不能被实例化，那么抽象类能被实例化吗？也不行。

那抽象类有啥用？

1、抽取公共代码，复用成员：多个子类有共同的字段、普通方法、构造逻辑，可以放到抽象父类。子类直接继承，不用重复写。比如所有猫都有名字、年龄，sleep()逻辑一样，就写在抽象 Cat 里，暹罗、布偶子类直接继承。

2、用抽象方法对子类做强制规范：抽象类专为继承设计，可通过抽象方法强制子类遵循规范：抽象方法仅定义方法签名，不提供实现。非抽象子类必须重写抽象方法，编译器会做校验。

比如抽象类 Cat 定义抽象方法run()，子类 Siamese 就必须实现run()，避免遗漏核心逻辑。

3、表达 “概念模板”，防止无意义实例 有些类只是抽象概念，不应该直接 new 对象。 比如 “猫” 是一个大类概念，现实里不存在一只 “单纯的猫”，一定是暹罗、布偶这种具体品种。 打上abstract，直接禁止new Cat()，从语法层面避免创建这种抽象概念的对象。
4、支持多态，统一入口 可以用抽象类做引用类型，接收所有它的子类对象（面向抽象，下面有）。

与继承的区别

需要区分的是：抽象类的抽象方法与直接继承时写新方法的区别（抽象方法 = 编译器强制的合同；各写各的 = 靠自觉的口头约定。）

1、编译器强制检查：子类忘记实现 → 编译直接报错；各写各的 → 运行时才发现，甚至调错方法。
2、支持多态：父类引用统一调用，新增子类时调用方代码零改动；没有抽象只能 instanceof + 强转，代码爆炸。
3、能向上转型：Shape s = new Circle(3); s.area(); 编译通过；没有契约，父类引用根本点不出 area()。
