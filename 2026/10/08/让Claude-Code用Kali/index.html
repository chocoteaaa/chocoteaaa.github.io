发表于2026-10-08|更新于2026-10-10
|总字数:5749|阅读时长:23 分钟|浏览量:

Claude Code 的 Agent 能力还是很不错的，本文手把手教你如何在 Kali 上配置 Claude Code，以及解决一些可能会遇到的问题，从而实现自动化渗透测试，不过我的 CC 还是很保守的。

这样的 Claude Code 工具建议部署在虚拟机或独立的物理设备中，不要在主力机上运行，因为自动化测试频繁调用脚本与工具可能会污染系统环境变量。

2、TUN 模式是一种底层的网络流量代理技术。它通过在操作系统中创建一个虚拟网卡，将所有出入设备的网络流量（无论是 TCP 还是 UDP）全部拦截并进行路由转发。在 Kali 上安装必须打开 TUN模式 才能成功下载 Claude Code。

更新注意事项

更新时遇到的具体问题还需具体解决，这里写一个我更新时遇到的问题，之后如果要更新先去源码仓库看一眼有没有bug，再考虑更新：

遇到未适配的新版本时，安装失败会覆盖现有版本且无法直接通过 claude update 回退 · Issue #214 · 0Chencc/clawgod

更新跑claude update命令，理论上 ClawGod 适配所有 Claude Code 版本，但遇到当 Anthropic 发布改了一些配置的新版 Claude Code，而 ClawGod 尚未适配时：

关键问题：

1、2.1.284：当前 ClawGod 发布版本可以正常打上补丁，第三方 API、auto-mode、放开安全限制、ClawGod skills 全部正常工作，就是我更新之前的版本。
2、2.1.285 / 2.1.286 / 2.1.287 / 2.1.293：无法打上现有除API的 ClawGod 补丁，作者还没有发布适配新版本的补丁包。
3、截止10.9，没有 2.1.284 之后的兼容版本，仓库 Issue 仅有人提 bug，暂未发布适配新版的 release。

原因：

CC 的 2.1.285 及以上（含我现在的 2.1.293），Clawgod 补丁正则失效，打补丁直接报错 Patching failed; regex stale：

clawgod 的”查找替换”里存的是旧原文，现在对不上了，一条替换失败，本来失败一条也不至于崩——但 clawgod 有个安全检查，它要判断”这次没找到”到底是哪种情况：

  • 代码被删了（那没事，跳过就行）
  • 还是代码被改了（那是它自己该更新了，得报错）

它的判断方法很糙：看源码里还有没有!=="firstParty"&&这串字样。问题是这串字在源码里到处都是，所以它误判成”代码改了但它没跟上”，直接整体罢工、中止安装。

现状：两个都是各自的最新版，只是兼容没跟上，最新的 clawgod（2.0.2，9月30日发的）还没适配最新的 Claude
Code（2.1.295，10月8日构建的）——中间 Claude Code 改了一句话，clawgod 这家还没跟上。

所以 ClaudeCode 此时干的只是第一层（接线 API），第二层（换色、解锁）从来没成功过。

Clude 配置

Github 上有很多便捷的可视化方便切换 API 、提示词、skills的工具。例如cc-switch，但是这个我用的时候一点输入框就直接页面卡住不刷新了，所以我这里就不用这些工具了，何况穷的也没有那么多大模型好切换的，所以这里直接在终端配置，这里以deepseek为例.

Claude Code 向外发请求永远是 Anthropic 消息格式（/v1/messages、tool_use、effort、anthropic-version 头） 国产模型只认 OpenAI 格式 /v1/chat/completions，无法直接解析 Anthropic 请求体。 需要 LiteLLM 这类网关做双向翻译：

  • Claude Code → 网关（接收 Anthropic 格式）→ 转 OpenAI 格式 → 国产模型 API
  • 模型返回 → 网关转回 Anthropic 规范 → 返回 Claude Code

DeepSeek：自带 /anthropic，不用协议代理，也不用网络代理

配置模型 API

模型选择看自己

1、DeepSeek-V4 Flash：代码强，toolcall 稳定，价格极低，CTF、exp 编写、漏洞分析非常香，很多人用来替换 sonnet 做 AI 打靶 Agent。
2、GLM-4 / GLM5 Flash：长文本强，读大量日志、源码，国内 API，合规安全。
3、Qwen3.5 系列：开源大模型，可 Ollama 本地跑在 Kali，零 API 费用，数据不出本机，缺点是高端推理弱，适合本地离线 Agent 练习。

这里用dp-flash，自带 /anthropic，直接修改 provider.json（推荐，ClawGod 原生支持）

若工作目录为：home/xx，则此目录下的记忆在：

在一个目录项目中，一般memory/是一个空文件，需要自己创建文件，如果记忆比较多可以像我一样建索引，再细分记忆内容，如果比较少可直接创建一个MEMORY.md直接这里面写就行了。

AI 渗透风险

重要前置：未经授权对任何系统开展渗透测试，无论是否使用 AI，都属于违法行为，会触犯《网络安全法》《刑法》非法侵入计算机信息系统罪等。下面讨论仅限企业内部授权的合规测试场景。

  1. 法律与责任风险 AI 生成指令易超出约定测试范围，误伤未授权资产；AI 操作日志可作为取证依据，越权操作需承担法律赔偿责任。
  2. 命令 / 载荷不可控风险 AI 自动选用高危参数、恶意 payload，缺少人工研判；参数理解偏差可能放大流量，造成业务卡顿、服务崩溃。
  3. 误报漏报，产生虚假安全感 AI 大量假漏洞消耗人力；复杂业务逻辑漏洞容易漏检，使人低估系统风险。
  4. 数据泄露风险 将内网 IP、Cookie、源码、凭证送入公有大模型，敏感测试数据上传至服务商；对话记录存在泄露风险。
  5. 提示词注入风险 目标页面恶意提示词劫持 AI，篡改测试策略、泄露测试计划与凭据。
  6. 人员能力退化 过度依赖 AI 复制 payload，不理解漏洞原理，无法识别异常、及时止损。
  7. 审计追溯困难 AI 自动执行动作链路不透明，操作记录难以满足等保安全审计要求。
  8. 攻击特征易被防御设备识别 AI 生成的 payload、请求流量特征较为统一，更容易被 WAF/IDS 检测拦截。
