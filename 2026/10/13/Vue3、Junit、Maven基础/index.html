Vue3框架

Vue 是一套渐进式 JavaScript 框架，专注于构建高效、简洁、可维护的前端页面与单页应用。相比原生 JS，Vue 摒弃了繁琐的 DOM 操作，基于数据驱动视图和响应式机制，大幅简化前端开发流程，是目前前后端分离项目、企业级开发的主流框架。

本文基于 Vue3 官方手册核心规范，从零讲解入门必备知识点，无需前端深厚基础，适配新手入门、后端开发者读懂前端 Vue 项目、日常联调排查问题。

Vue 核心特点

Vue3 是当前最新稳定版本，相较于 Vue2，性能更强、体积更小、API 更规范，核心优势集中在三点：

  • 数据驱动视图：无需手动操作 DOM，修改数据自动更新页面，告别原生 JS 繁琐的节点增删改查
  • 响应式机制：数据变化自动监听，视图实时同步，是 Vue 最核心的底层能力
  • 组件化开发：页面拆分为独立可复用组件，代码复用率高、维护性强，适配大型项目开发
  • 渐进式框架：可嵌入页面局部使用，也可搭建完整大型项目，灵活适配各类开发场景

Vue3 两种入门使用方式

Vue3 支持CDN 快速引入和脚手架项目搭建两种方式，前者适合入门测试、简单页面，后者是企业开发标准方式。

Vue 核心基础概念

挂载容器与应用实例

Vue 应用必须依托 DOM 容器渲染，通过 createApp 创建应用实例，mount() 方法指定挂载容器，一个 Vue 实例对应一个独立页面模块，互不干扰。

模板语法

Vue 模板是 HTML 扩展语法，可直接在页面中解析 Vue 数据与表达式，核心分为插值语法和指令语法。

插值语法 （花括号套花括号） // 直接写出来 hexo 要报错

用于页面文本渲染，支持变量、简单表达式运算，可直接展示响应式数据。

Vue 常用基础指令（完整实战）

指令是 Vue 内置的核心特性，以v- 为前缀，用于替代原生 DOM 操作，快速实现文本渲染、条件判断、列表遍历、事件绑定、属性绑定、表单双向绑定等功能。是 Vue 模板开发的基础核心，也是前后端联调页面数据展示、交互的必备知识点。

以下为开发、联调最高频的全套基础指令，附带实战案例，贴合后端对接页面的真实开发场景。

文本渲染指令 v-text / v-html

作用：v-text 用于纯文本渲染，直接覆盖标签内原有文本内容，不解析 HTML 标签；v-html 可解析后端返回的 HTML 字符串，渲染富文本内容。

语法：<标签 v-text="变量"></标签> 、 <标签 v-html="变量"></标签>

参数说明：变量为响应式数据，存储后端返回的普通文本 / HTML 富文本字符串。

简化写法：无简写，直接使用原指令。

条件渲染指令 v-if / v-else-if / v-else

作用：用于根据数据条件判断元素是否渲染，条件不成立时直接销毁 DOM 节点，适合切换频率低、权限控制、数据为空判断场景，常用于后端数据为空、用户身份展示判断。

语法：<标签 v-if="条件表达式"></标签>

参数说明：条件表达式返回布尔值/状态码，常用来判断后端返回的请求状态、数据是否为空。

简化写法：无简写，配套使用 v-else-if、v-else 实现多条件分支。

显示隐藏指令 v-show

作用：通过 CSS 的 display 属性控制元素显示隐藏，DOM 节点始终存在，只是视觉隐藏。适合频繁切换显示隐藏的弹窗、按钮、模块场景，性能优于 v-if。

语法：<标签 v-show="条件表达式"></标签>

参数说明：表达式为 true 显示元素，false 隐藏元素，适配弹窗、下拉框等频繁切换场景。

简化写法：无简写。

双向绑定指令 v-model

作用：专门用于表单元素（input、textarea、select），实现数据与视图双向同步，输入框修改内容自动同步JS数据，JS数据修改自动回显输入框，是前端收集表单参数、提交后端接口的核心指令。

语法：<input/textarea/select v-model="表单变量">

参数说明：表单变量为响应式数据，与后端实体类字段一一对应，自动同步输入内容。

简化写法：无简写。

列表循环指令 v-for

作用：开发最高频指令，用于遍历后端返回的数组列表，批量渲染页面数据，支持遍历数组、对象，必须搭配 :key 唯一标识，提升渲染性能、避免数据错乱。

语法：<标签 v-for="(item, index) in 数组变量" :key="唯一值"></标签>

参数说明：item 为数组每一项数据，index 为下标索引，数组变量为后端返回的列表数据，key 为唯一标识。

简化写法：可省略 index，简写为 v-for=”item in 数组变量”。

属性绑定指令 v-bind（简写 :）

作用：动态绑定 HTML 标签属性（src、href、class、style、自定义属性等），所有动态变化的属性必须使用该指令，常用于动态跳转地址、动态样式、后端图片地址回显。

语法：<标签 v-bind:属性名="变量/表达式"></标签>

参数说明：属性名即标签原生属性（src、href、class），变量存储后端返回的动态属性值。

简化写法：**:**
例：:src=”imgUrl”、:href=”detailUrl”。

事件绑定指令 v-on（简写 @）

作用：绑定页面点击、输入、回车等各类事件，实现页面交互、接口提交、数据重置等业务逻辑，是前端交互、前后端数据提交的核心指令。

语法：<标签 v-on:事件名="事件方法"></标签>

参数说明：事件名为原生事件（click、input、submit），事件方法为自定义交互逻辑（请求接口、重置表单）。

简化写法：**@**
例：@click=”queryData”。

核心规范

  • 静态属性直接写原生属性，动态变化属性必须用 : 绑定
  • 页面交互、接口提交事件统一使用 @ 绑定
  • 表单参数收集统一用 v-model，自动同步参数，无需手动获取 DOM 值
  • 列表渲染必须加 :key，避免后端数据刷新后列表错乱
  • 高频切换用 v-show，状态判断、空数据展示用 v-if

Vue3 响应式核心（ref）

响应式是 Vue 的灵魂，Vue3 组合式 API 推荐使用 ref 创建响应式数据，支持基础类型、引用类型数据，修改数据可自动触发视图更新。

模板中使用 ref 数据无需加 .value，仅在 JS 逻辑中修改数据需要通过 .value 赋值。

Vue3 两种编程风格

Vue3 兼容两种 API 风格，适配不同开发场景，官方推荐新项目统一使用组合式 API。

  • 选项式 API：配置式写法，结构清晰、上手简单，适合小型页面、简单场景开发
  • 组合式 API：Vue3 主推写法，逻辑聚合、复用性强，适合大型复杂项目，便于代码维护与逻辑抽离

基础生命周期

生命周期是组件从创建、挂载、更新到销毁的完整过程，Vue 提供对应钩子函数，可在指定阶段执行自定义逻辑，onMounted 是开发最高频钩子，常用于页面初始化、接口请求。

Vue3 与后端交互核心

学习 Vue 的核心目的不是单纯写前端页面，而是实现前后端数据交互、完成项目业务联调。Vue 本身不具备专属网络请求能力，日常开发基于原生 Fetch、Axios 向后端发送请求，完成数据查询、新增、修改、删除。

本节聚焦后端开发者必须掌握的 Vue 联调逻辑，包含初始化请求、GET/POST 传参、参数格式、跨域处理、异常捕获、数据回显全套实战，完全贴合企业前后端分离项目开发模式。

前后端交互核心流程

Vue 前端 <=> 后端接口 标准数据流：

页面挂载初始化 => Vue 发起网络请求 => 后端接收参数、执行业务逻辑、返回 JSON 数据 => Vue 接收响应、渲染页面、数据回显

页面初始化请求规范

所有页面初始化数据（列表、详情、下拉数据），统一在 onMounted 生命周期中请求，这是 Vue 项目固定开发规范。页面 DOM 加载完成后自动调用后端接口，实现页面数据自动渲染。

GET 请求实战（查询数据）

GET 用于查询无副作用数据，参数拼接在 URL 中，适配后端 @GetMapping 接口，多用于列表查询、数据详情查询。结合 async/await + try-catch 实现优雅异步请求与异常捕获。

POST 请求实战（提交数据）

POST 用于提交新增、修改数据，参数放在请求体中，适配后端 @PostMapping 接口，后端通过 @RequestBody 接收 JSON 格式参数，是前后端联调最常用的传参方式。

前后端联调核心注意点

  • 参数格式统一：Vue 传 JSON 格式数据，后端接口必须用 @RequestBody 接收；表单格式参数无需 JSON 序列化
  • 字段命名一致：前端表单字段名必须和后端实体类属性名一致，避免参数映射失败
  • 请求头规范：POST 传 JSON 必须携带Content-Type: application/json 请求头
  • 异常统一捕获：所有接口请求必须搭配 try-catch，防止前端页面报错卡死

前后端联调跨域问题

Vue 前端本地启动端口（如 5173）与后端服务端口（如 8080）不一致，浏览器会触发跨域拦截，这是联调最高频问题。

核心结论：跨域由后端解决，前端无需修改任何代码。

Java 后端常用解决方案：

  • 接口类/方法添加 @CrossOrigin 注解快速放行跨域
  • 全局 CORS 配置类统一配置跨域规则
  • 网关层统一配置跨域放行（微服务项目）

后端视角常见报错排查

  • 404：前端请求地址、请求路径与后端接口路径不匹配
  • 405：请求方式不匹配（后端GET接口，前端发POST请求）
  • 400：JSON格式错误、参数缺失、字段不匹配、未序列化参数
  • 500：后端代码异常、参数解析异常、数据库操作失败
  • 跨域报错：后端未配置跨域放行

Vue 联调最终规范

  1. 页面初始化数据统一在 onMounted 生命周期请求后端接口；
  2. 查询用 GET、新增/修改用 POST，严格匹配后端接口请求方式；
  3. JSON 传参必须序列化+配置请求头，适配后端 @RequestBody 接收；
  4. 所有异步接口使用 async/await + try-catch 统一处理；
  5. 跨域、参数报错、状态码问题优先从后端接口排查。

Maven核心介绍

在 Java 后端开发中，所有 SpringBoot、SSM、微服务项目，全部基于 Maven 构建。可以说：不会 Maven，就无法正常开发 Java 项目。

Maven 是一款基于 Java 的项目构建与依赖管理工具，由 Apache 开发，核心用来简化 Java 项目的编译、打包、依赖管理。

为何需要 Maven？

写 Java 项目时，你会遇到几个很烦的问题：

  1. 需要一堆第三方库：比如用 Spring、MySQL 驱动、日志库，得手动去官网下载 Jar 包。
  2. Jar 包还有依赖：Spring 又依赖别的库，你得一个个找齐，版本还得对得上。
  3. 编译、打包、运行：每次都要敲一长串命令，或者手动配置 IDE。

Maven 就是来解决这些问题的。它做两件事：

  • 帮你下载和管理 Jar 包（依赖管理）
  • 帮你编译、测试、打包（构建自动化）

你只需要在一个叫 pom.xml 的文件里写清楚”我要什么”，Maven 负责”怎么拿到、怎么构建”。

什么是 scope？

scope 控制这个依赖在什么阶段可用：

scope 作用范围
compile（默认） 编译、测试、运行都可用
test 只在测试代码中可用
provided 编译和测试可用，打包时不带（如 Servlet API）
runtime 编译不用，运行和测试用（如 MySQL 驱动）

传递依赖

如果 A 依赖 B，B 又依赖 C，Maven 会自动把 C 也下载下来。这叫传递依赖。

但这也可能带来版本冲突：不同库引用了同一个库的不同版本。Maven 的默认规则是：

  1. 路径最短优先：依赖树里离你最近的版本胜出。
  2. 声明顺序优先：路径一样长时，先声明的胜出。

生命周期

一条命令完成构建，Maven 定义了一套标准的构建流程，常用命令按顺序如下：

命令 作用
mvn clean 删除 target 目录，清理上次构建产物
mvn compile 编译 src/main/java 下的源代码
mvn test 运行 src/test/java 下的测试
mvn package 打包成 jar 或 war，放在 target 目录
mvn install 打包并安装到本地仓库，供其他项目引用
mvn deploy 发布到远程仓库，供团队使用

关键点：这些阶段是顺序执行的。运行 mvn install 时，Maven 会先执行 compile、test、package，最后才 install。所以你不需要一条条敲，直接跑最终目标即可。

常见问题排查

1. 依赖下载不下来

  • 检查网络，或配置镜像。
  • 删掉本地仓库里对应的目录，重新下载。
  • 用 mvn clean install -U 强制更新快照依赖。

2. 版本冲突

用 mvn dependency:tree 看依赖树，找到冲突的库，用 <exclusions> 排除，或在 <dependencyManagement> 里锁定版本。

3. 编译报”找不到符号”

  • 检查 pom.xml 里有没有加对应依赖。
  • 检查 scope 是不是设错了，比如把 compile 写成了 test。

Maven 的核心就三件事：

  1. pom.xml 声明依赖：要什么库，写坐标，Maven 自动下载。
  2. 生命周期命令构建：clean、compile、test、package、install，一条命令走完流程。
  3. 约定优于配置：标准目录结构 + 默认插件配置，让你少写很多配置。

掌握这些，日常开发中 90% 的 Maven 场景都能应付。剩下的多模块继承、依赖冲突排查、插件定制，用到了再查即可。

单元测试 Junit

在后端开发中，写完接口、业务代码后，传统测试方式是启动项目、调用接口、查看控制台日志，效率极低且容易漏测边界场景。JUnit 是 Java 生态最主流的单元测试框架，无需启动完整项目，可快速对工具类、业务方法、接口逻辑进行独立测试，是后端开发、代码调试、项目提测的核心必备技能。

本文主打后端实战风格，不讲冗余理论，聚焦日常开发高频用法，适配 SpringBoot 项目，从零掌握 JUnit 基础使用、常用注解、断言机制、实战场景，完全贴合企业级开发规范。

核心概念

什么是单元测试

单元测试是对代码中最小执行单元（通常是单个方法、工具类、业务逻辑块）进行的自动化测试，目的是验证代码逻辑是否符合预期、排查 Bug、校验边界值，避免改代码引发隐性故障。

JUnit 核心优势（后端视角）

  • 无需启动完整项目：单独运行测试方法，秒级执行，调试效率极高
  • 自动化校验结果：通过断言自动判断结果对错，无需人工看日志比对
  • 精准定位 Bug：测试失败直接提示错误位置、预期值与实际值，快速排错
  • 适配迭代开发：后续修改代码，运行单元测试即可校验原有逻辑是否失效

开发规范

企业开发统一规范：业务核心方法、工具类、计算逻辑、条件分支复杂代码，必须编写单元测试。

JUnit 环境搭建（SpringBoot ）

目前主流项目统一使用 JUnit5（Jupiter），SpringBoot 2.2+ 版本默认集成，无需手动下载依赖，直接引入 starter 即可。

Maven 依赖

项目目录规范

Java 项目严格区分源码与测试代码，目录结构统一：

  • 业务源码：src/main/java
  • 测试源码：src/test/java

测试类包名需与业务类保持一致，方便管理与对应测试。

JUnit5 核心常用注解

注解是 JUnit 单元测试的核心，所有测试逻辑、执行时机、测试配置全部依赖注解实现。下面按作用、语法、参数说明、简化/补充说明统一格式讲解，贴合实战使用。

@Test 测试方法注解

作用：标记当前方法为单元测试方法，被该注解修饰的方法可独立运行测试。
语法：@Test 修饰在公共无返回值方法上方
参数说明：无参数
补充说明：测试方法必须是 public void、无参数、无返回值，普通方法无该注解无法被 JUnit 识别运行。

@BeforeEach 前置注解

作用：每一个测试方法执行前都会自动执行，用于初始化数据、初始化对象、开启资源。
语法：@BeforeEach 修饰初始化方法
参数说明：无参数
补充说明：多个测试方法时，每次执行测试都会重新执行前置方法，保证测试数据独立不干扰。

@AfterEach 后置注解

作用：每一个测试方法执行后都会自动执行，用于关闭资源、清空临时数据、释放连接。
语法：@AfterEach 修饰资源释放方法
参数说明：无参数
补充说明：常用于关闭流、清空测试缓存、重置对象数据。

@BeforeAll 全局前置注解

作用：整个测试类执行前只执行一次，用于全局初始化，如加载配置、创建数据库连接。
语法：@BeforeAll 修饰静态方法
参数说明：无参数
补充说明：被修饰方法必须是 static，全局只执行一次，性能优于 BeforeEach。

@AfterAll 全局后置注解

作用：整个测试类所有方法执行完毕后只执行一次，用于全局资源销毁。
语法：@AfterAll 修饰静态方法
参数说明：无参数
补充说明：被修饰方法必须是 static，常用于关闭全局连接、销毁资源。

@Disabled 忽略测试注解

作用：禁用当前测试类/测试方法，被修饰的内容不会执行测试。
语法：@Disabled(备注信息)
参数说明：可选参数，填写忽略原因，方便团队协作查阅
补充说明：临时调试、方法未完善、无需测试时使用，避免注释代码。

@DisplayName 自定义名称注解

作用：自定义测试类、测试方法的展示名称，替代默认类名/方法名，可读性更强。
语法：@DisplayName(“自定义名称”)
参数说明：字符串参数，填写测试功能描述
补充说明：企业项目必备，清晰标注测试场景，方便团队查看测试报告。

JUnit 生命周期

通过完整代码演示所有注解的执行顺序，彻底掌握 JUnit 执行机制，适配所有后端测试场景。

执行顺序总结：全局初始化 → 方法前置 → 测试方法 → 方法后置（循环所有测试方法） → 全局销毁

JUnit 核心断言机制

断言是单元测试的核心灵魂，代替人工日志判断，自动校验代码执行结果是否符合预期，结果不匹配直接报错，精准定位 Bug。所有断言方法均来自 org.junit.jupiter.api.Assertions。

常用断言方法大全

  • **assertEquals(预期值, 实际值)**：判断两个值是否相等（字符串、数值、基本类型）
  • **assertNotEquals(预期值, 实际值)**：判断两个值是否不相等
  • **assertNull(对象)**：判断对象为空
  • **assertNotNull(对象)**：判断对象非空
  • **assertTrue(布尔表达式)**：判断结果为 true
  • **assertFalse(布尔表达式)**：判断结果为 false

SpringBoot 整合 JUnit 业务层

后端开发最常用场景：测试 Service 业务层代码，无需启动项目，直接注入 Bean 测试业务逻辑。

核心注解：@SpringBootTest

作用：加载 SpringBoot 完整上下文环境，支持依赖注入，可直接使用 @Autowired 注入 Service、Mapper、Component 等容器 Bean。
语法：类上添加 @SpringBootTest
参数说明：无参数，默认加载项目主配置、扫描所有容器组件

JUnit 异常测试

后端开发经常需要测试异常场景，如参数非法、空指针、数值越界，JUnit 可精准捕获预期异常，验证代码容错性。

核心作用：校验代码是否按照预期抛出异常，避免线上出现未知报错，完善代码容错逻辑。

JUnit 规范和总结

规范

  • 测试类命名：业务类名+Test，如 UserServiceTest、OrderMapperTest
  • 测试方法命名：test+功能场景，如 testGetUserById、testAddUser
  • 所有测试类、方法必须添加 @DisplayName，标注清晰场景
  • 核心业务、分支逻辑、边界值、异常场景必须覆盖测试

总结

  • JUnit5 核心是注解+断言，实现自动化测试，替代人工调试
  • 生命周期注解区分全局/局部、前置/后置，适配不同初始化场景
  • 断言自动校验结果，是判断测试成败的唯一标准
  • @SpringBootTest 整合容器，可测试所有业务层、数据层代码
  • 支持异常测试、边界测试，全面覆盖线上业务场景

价值

单元测试是后端开发者的调试神器，无需反复启动项目、无需对接前端、无需模拟接口请求，即可快速验证代码逻辑，大幅提升开发效率，减少线上 Bug，是企业级开发的必备基础能力。
