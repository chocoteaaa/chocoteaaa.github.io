IO流

核心

IO 即 Input/Output，也就是输入与输出。我们以内存作为参照中心来理解：

  • Input（输入）：将外部的数据读入内存。比如从磁盘读取文件、从网络接收数据到内存。
  • Output（输出）：将内存中的数据写出到外部。比如把内存数据写入磁盘文件、发送数据到网络。

为什么数据必须读到内存中才能处理？ 程序代码本身运行在内存中，待处理的数据同样需要加载进内存，才能转为字节数组、字符串等形式供代码操作。 放到 Java 的视角理解输入：就是把文件这类外部资源的数据加载到内存，封装成 byte[]、String 等 Java 可识别的数据类型，后续业务代码才可以对数据做处理。

流的分类

分类维度 类别 说明
数据单位 字节流 操作字节 byte，万能流：文本、图片、视频都可以；基类 InputStream / OutputStream
字符流 操作字符 char，底层还是字节 + 编码；只适合文本；基类 Reader / Writer
流向 输入流 从数据源读入程序：InputStream、Reader

功能 节点流 直接对接数据源（文件、数组、管道），原始流
处理流 包装节点流，增强功能（缓冲、转换、对象序列化），装饰器模式

File 类

在计算机系统中，文件是非常重要的存储方式。Java 的标准库java.io提供了File对象来操作文件和目录。

File 类是操作文件 / 文件夹本身（文件元信息）能新建、删除、重命名文件和目录；IO 流是操作文件本身内容。

想要在Java程序中表示一个真实存在的文件或目录，那么必须有一个 File 对象，但是 Java 程序中的一个 File 对象，可能没有一个真实存在的文件或目录。

这个方法会读取输入流的下一个字节，并返回字节表示的int值（0~255）。如果已读到末尾，返回-1表示不能继续读取了。

关闭流

为了不占用内存，在程序完成操作后需要释放内存，InputStream和OutputStream都是通过close()方法来关闭流。关闭流就会释放对应的底层资源。

避免 IO 错误

在读取或写入IO流的过程中，可能会发生错误，这些底层错误由Java虚拟机自动封装成IOException异常并抛出。因此，所有与IO操作相关的代码都必须正确处理IOException。

用try ... finally来保证InputStream在无论是否发生IO错误的时候都能够正确地关闭，及时释放资源，但用try ... finally来写代码会感觉比较复杂，可用 Java 7 引入的新的try(resource)的语法，只需要编写try语句，让编译器自动为我们关闭资源：

编译器只看try(resource = ...)中的对象是否实现了java.lang.AutoCloseable接口，如果实现了，就自动加上finally语句并调用close()方法。InputStream和OutputStream都实现了这个接口，因此，都可以用在try(resource)中。

在方法定义的时候，使用throws Xxx表示该方法可能抛出的异常类型。调用方在调用的时候，必须强制捕获这些异常，否则编译器会报错。

缓冲

逐个字节读取流效率低，推荐使用缓冲区批量读取。 InputStream提供两个批量读方法：

1、int read(byte[] b)：读取字节填入字节数组，返回读到的字节数量
2、int read(byte[] b, int off, int len)：从数组指定偏移位置开始，最多读 len 个字节

要点：byte 数组就是缓冲区；方法尽可能读满数组，但不会超出数组容量。 返回值：实际读到的字节数；返回-1代表读到末尾，无数据。

字节流-OutputStream

OutputStream

OutputStream也是抽象类，它是所有输出流的超类。这个抽象类定义的一个最重要的方法就是void write(int b)：

这个方法会写入一个字节到输出流。要注意的是，虽然传入的是int参数，但只会写入一个字节，即只写入int最低8位表示字节的部分（相当于b & 0xff）。

和InputStream类似，OutputStream也提供了close()方法关闭输出流，以便释放系统资源。要特别注意：OutputStream还提供了一个flush()方法，它的目的是将缓冲区的内容真正输出到目的地。

flush () 原理

为提升 IO 效率，数据不会直接写入磁盘 / 网络，而是先暂存到内存缓冲区（byte 数组），缓冲区满了才一次性写出。 flush()作用：强制把缓冲区里现有数据立刻写出，不用等缓冲区填满。

什么时候不用手动 flush

缓冲区满会自动刷；调用close()关闭流前，会自动执行 flush。

什么时候必须手动 flush

网络实时传输场景（聊天程序）：消息量很小，缓冲区一直没填满，数据就一直卡在内存缓冲区，对方收不到。这时写完一条消息就要调用flush()，强制立刻发送。

缓冲

输入流同样有缓冲区。调用read()读单个字节时，系统一次性预加载一批数据到缓冲区，后续读字节直接从内存缓冲区拿，减少磁盘 IO；缓冲区取完，才会再次去磁盘加载数据。

阻塞

和InputStream一样，OutputStream的write()方法也是阻塞的。

序列化

序列化：把 Java 对象转为二进制数据，本质就是byte[]字节数组。 作用：序列化后的字节数组，可以保存到文件，或者通过网络传输，实现对象持久化、网络传输。

反序列化：序列化的逆过程，把二进制字节数组，重新还原成 Java 对象。

序列化前提

想要类的对象能够序列化，这个类必须实现java.io.Serializable接口。

Serializable是标记接口（Marker Interface）：接口里面没有任何抽象方法。 实现它只是给类打上一个标记，告诉 JVM：这个类的对象允许序列化，不需要重写任何方法。

序列化：ObjectOutputStream

ObjectOutputStream可以把对象写入字节流。 既能写入int、boolean等基本类型、String，也能写入实现了 Serializable 接口的对象。

注意：写入对象时会附带大量类型描述信息，所以生成的二进制数据体积偏大。

反序列化：ObjectInputStream

ObjectInputStream用来从字节流读取数据，还原对象。

readObject()返回 Object 类型，需要强制转型成目标类。

常见异常

  1. ClassNotFoundException：反序列化时找不到对应的类。比如网络传输对象，接收端没有这个类。
  2. InvalidClassException：类版本不匹配。序列化和反序列化两端的类结构不一样（比如字段类型改动）。

serialVersionUID 版本号（重点）

为解决类修改后版本不兼容问题，可以在类中定义静态常量serialVersionUID，作为序列化版本标记，一般 IDE 可以自动生成。

修改类结构时，可以手动修改这个版本号，JVM 会阻止不同版本的类进行反序列化。

反序列化重要特点

反序列化创建对象时，不会调用构造方法！ 对象直接由 JVM 根据二进制数据生成，构造器代码不会执行。

安全问题

因为反序列化可以绕过构造方法直接创建对象，如果传入恶意构造的二进制数据，可能执行恶意代码，造成严重漏洞。

小结：Java 原生序列化有安全风险、版本兼容麻烦。实际项目更推荐 JSON 这类方案，只保存数据，不保存 Java 类型信息。
