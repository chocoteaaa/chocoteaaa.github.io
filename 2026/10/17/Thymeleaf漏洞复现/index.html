极简Thymeleaf漏洞复现(CVE-2026-40478...)

发表于2026-10-17|更新于2026-10-18
|总字数:1853|阅读时长:8 分钟|浏览量:

前情基础

Thymeleaf 是 Java 生态的模板引擎（和 Jinja2、Freemarker、Velocity 同类），专门用于 SpringBoot 项目，用来渲染 HTML 页面。

Vulhub 没有专门的靶场，因此写了一个极其简单的故意保留漏洞的 Spring Boot Web 应用，用于学习 / 演示 Java Thymeleaf 服务端模板注入（SSTI）

本靶场以 IDEA 为例，项目不对应”一个” CVE —— 它复现的是 Thymeleaf SSTI 的通用技术，而这种经典形态的根因在应用代码(把输入拼进视图名)，不是 Thymeleaf 库的缺陷，所以没有 CVE，但可参考下表：

CVE 影响版本 修复版本 说明
CVE-2026-40478 Thymeleaf ≤ 3.1.3 3.1.4.RELEASE CVSS 9.1;预检只拦 new (ASCII 空格),tab/换行溜过;类型黑名单只限 java.*
CVE-2026-40477 Thymeleaf ≤ 3.1.3 3.1.4.RELEASE 同批;未限制可访问对象范围
CVE-2026-41901 Thymeleaf ≤ 3.1.4 3.1.5.RELEASE 后续绕过补丁;CVSS ~9

都是 2026 啊，看来还是新鲜出炉的，这不得好好看看。

项目

说明

一个最小化的 Spring Boot + Thymeleaf 应用。它的 @Controller 故意把用户输入拼接进「视图名 / fragment 选择器」再返回 —— 这正是 Thymeleaf SSTI 的经典成因。

攻击者构造带 __${...}__ 的输入，即可让 Thymeleaf 把输入当 SpEL 表达式求值，进而 RCE。

Thymeleaf fragment SSTI 流程原理

更加详细底层的基础代码原理这里就不写了，之后会专门系统总结并回来补充的，这里就只写流程了：

1、用户发起 GET 请求：/fragment?section=payload
2、Spring 接收请求，执行 fragment 方法，取出参数 section；
3、代码拼接字符串："welcome :: " + section；
4、将拼接后的字符串交给 Thymeleaf 视图解析器；
5、Thymeleaf 识别语法 模板::片段，对::后的内容模板引擎解析执行；
6、当 section 是恶意 OGNL 表达式，Thymeleaf 会执行 OGNL 代码，造成 RCE、读取文件。

区分：

  • 安全场景：用户输入放进 Model，模板${userInput}输出 → 自动转义，纯文本输出；
  • 漏洞场景：用户输入拼在视图名 /fragment 片段表达式 → Thymeleaf 引擎直接解析表达式，触发 SSTI。

防护原则

1、升级 Thymeleaf 版本到 3.0.12 及以上（最直接）；
2、视图名称、fragment 片段名称禁止拼接用户输入；采用固定值 + 白名单；
3、用户输入只允许作为 Model 数据传入模板渲染，不要参与视图解析；
4、输入做白名单校验，严格限制输入内容；
5、最小权限运行 Web 服务账号，降低 RCE 之后危害。

Flask Jinja2 SSTI VS Thymeleaf SSTI

项目 Jinja2(Flask) Thymeleaf(SpringBoot)
模板语言 Jinja2 语法 OGNL 表达式
触发入口 渲染时把用户输入当做模板内容渲染 视图名 /fragment 片段可控，__${}__预处理器
漏洞核心 模板渲染函数直接接收用户输入 视图解析阶段解析 fragment 表达式
payload 风格 {{xxx}} __${xxx}__
